GETTING STARTED
- Double-click "IU0VYT Flash.exe". The home screen "🏠 Home" opens and at the top there
  are the fixed tabs "🏠 Home", "📻 Models", "Repeater archive" and "ℹ Info"; every
  radio chosen from the gallery (including Baofeng K67 Pro and Bajeton 8300) opens in
  an extra tab, which is closed with ×.
- When updating from version 2.x just replace the executable: archive, settings and
  copies stay where they are.
- When updating from version 2.1 or earlier (GestioneCanali.exe): repeater archive,
  settings and copies stay the same (folder %APPDATA%\GestioneCanaliRadio); the old
  GestioneCanali.exe can be deleted.
- The program has no digital signature: at the first start Windows may show "Windows
  protected your PC". Click "More info" and then "Run anyway".
- The window uses the WebView2 component, already present in Windows 11. If it were
  missing, the program opens in the default browser and a small window lets you close
  it.
- Only one copy of the program can be open at a time.

HOW TO WORK
With the programming cable:
1. "📻 Read from radio…": the radio's channels appear in the table.
2. Edit the channels; also save them to a file (Save as…), to keep a copy.
3. "📻 Write to radio…".
With the files (as in version 1.0):
- Open a .xlc file (K67 Pro) or .dat file (Bajeton 8300) saved with the original
  program or with this one, edit, save (Ctrl+S). The files saved here can also be
  opened and written with the original program.
When you save over an existing file, the previous version is kept next to it with the
.bak extension (e.g. k67.xlc.bak).

MODEL GALLERY
- The "📻 Models" tab shows all the Baofeng radios (catalogue and download page of
  baofengradio.com), Bajeton (bajeton.com) and, since 4.0, those of the other brands
  handled (Quansheng, Retevis, Radtel, Radioddity, TIDRADIO, MaxTalker, Abbree, Intek,
  Maverick, BTECH, WLN, Zastone, Luiton, TID and, since 4.1, Hiroyasu, Talkpod,
  Anysecu). Search by brand or name, including alternative names (e.g. UV-5RA, MINI-5,
  GT-3TP, UV-K5), and filter by brand ("All brands" menu), type (amateur radio, DMR,
  GMRS / FRS, PMR446 and licence-free, for children), radios with channels via cable
  or with firmware.
- At the top the "COMPATIBLE MODELS: N", handled by this program ("Channels" and
  "Firmware" labels), at the bottom the "NON-COMPATIBLE MODELS: N", which can be
  programmed only with the manufacturer's program or with free programs: for these
  there are the official links to programs, firmware and manuals. N is the number of
  models (with search and filters, those shown). Since 4.3 a thick line separates the
  two parts.
- In each part the radios are divided by type: Amateur radio (VHF/UHF), DMR (digital),
  GMRS / FRS (USA), PMR446 and licence-free radios, For children; within each division
  the radios are separated by brand (first Baofeng, then Bajeton, then the others in
  alphabetical order, with the number of models of each) and the models are in
  alphabetical order (UV-5R before UV-17). Each radio's card shows the brand, each
  with its own color (Baofeng in blue, Bajeton in orange, Quansheng in green, Retevis
  in red, Radtel in purple…).
- Every model has its own card even when it is handled like another one: for example
  UV-5R, UV-5RA, UV-5RE, GT-3 use the same driver, and so do BF-888S and BF-777S. The
  card's note lists the models with the same handling. For the equivalent models
  listed in CHIRP's table (chirp/share/model_alias_map.yaml, e.g. GT-1 = BF-888, GT-5
  = UV-82, UV-10R = BF-F8HP) the note says so: the compatibility is the one indicated
  by CHIRP, not by the manufacturer.
- Click on a radio: its channel tab, the firmware update or the list of links opens.
  If the radio exists in several versions (e.g. UV-5RX3, UV-5R+Pro) choose yours: if
  it is not the right one the radio does not answer and is not modified.

RADIO SETTINGS (3.6)
- "⚙ Settings…" button in the radio's tab, after reading the radio via cable or
  opening one of its files. On the left the groups (e.g. "Receive and transmit",
  "Display, sounds and keys", "DTMF"), at the top the search. Each item has:
    ⓘ  description of the item (hover with the mouse; one click keeps it open below);
    ⚠  on sensitive items: the warning is in the description and, before applying, a
    window summarizes the warnings and asks for confirmation.
  Changed items are highlighted; "Apply" writes them into the tab's memory (which
  becomes "modified"): then save the file or write to the radio as for channels. "Undo
  changes" goes back to the values read.
- Sensitive items: passwords (power-on, read, write), frequency limits and transmit
  enable per band, transmit disabled, transmit time-out, VOX, reset and menu items,
  PTT-ID and transmitted codes, alarm that transmits, repeater function, remote kill,
  Bluetooth programming, keypad lock.
- K67 Pro / 5RH Pro (53 items): from the «5RH PRO» program, methods ConvertSetting and
  SettingConvert.
- Bajeton BJ-8300 (40 items; 41 in files of BT-11_CPS v1.0.9, with "Channel
  division"): the program's «Optional Features» window; each item is a number of the
  object saved in the .dat file, changed in place (the file stays identical to the one
  the program would save).
- Bajeton BJ-9000, Radtel RT-950 Pro and RT-950 (57 items): the «Optional Features»
  window of the manufacturer's programs; only the bits of each item are changed, the
  other bytes stay as the radio has them. The active zones of the bands are 10 or 15
  depending on the firmware version.
- Radios handled with the CHIRP drivers (63 families: UV-5R, UV-17 Pro, waterproof
  models, BF-888S, UV-B5, BF-T1, BJ-7800, BJ-7700, H series…): each family's table is
  derived from the CHIRP code (for each item CHIRP is made to write every value and
  the changed bits are observed) and the items are translated. Calibration, test and
  factory items are not included. Texts with non-Latin characters (e.g. Chinese names

- Baofeng RD-5R and DM-1801 (4.10, 31 items): general settings of the Radioddity GD-77
  family as described by qdmr (DMR name and ID as in dmrconfig); passwords are not
  touched. Baofeng DM-1701 (4.10): name, DMR ID and power-on texts, the only fields on
  which dmrconfig and qdmr agree.
- Not yet available: D series, T17 / T18, GT-18, T9, GT-22, GT-68, BF-C2, BF-88ST,
  BF-9700 / BF-S56 Max, DM-5000, DR-1801UV and the models of the UV-17 Pro family that

READING AND WRITING VIA CABLE
- Connect the cable, turn on the radio, choose the cable's COM port in the window (the
  driver name helps to recognize it, e.g. "USB-SERIAL CH340 (COM3)"). If the port does
  not appear, install the cable driver and press "Refresh".
- The protocol is that of the manufacturers' original programs (K67 Pro CPS, 5RH_PRO,
  and Bajeton's BT-11_CPS), derived from their code: same commands, same encryption,
  same checks, same pauses.
    K67 Pro: 19200 baud (the radio may ask for 115200 by itself, as in the original),
    optional programming password (max 8 characters).
    Bajeton 8300: 57600 baud.
- Before writing, by default, the program reads the radio and saves a backup copy of
  it; after writing it reads the radio again and compares the channels. If the radio
  restarts at the end of writing, the re-read waits and tries again until the radio
  answers again (up to 45 seconds, 3.9.2).
  Copies and reads are in %APPDATA%\GestioneCanaliRadio\copie_radio (they open like
  normal .xlc/.dat files). If the backup copy fails, nothing is written.
- The whole memory is written as the original program does: together with the channels
  also the general settings contained in the file or read you are working on (menus,
  VFO, zones, DTMF…). To leave them unchanged, start from a read of the radio. On the
  K67 the first 128 bytes (radio data, model, ranges) are never overwritten: the
  program reads them from the radio, like the original.
- Checks before writing (as in the original): K67 with a frequency band different from
  the file's or "BF-K6" model not read first → write refused; data that cannot be
  converted → error before connecting to the radio.
- Reading and the backup copy can be interrupted; writing cannot (the radio would be
  left with incomplete data). If writing is interrupted (cable unplugged, radio turned
  off) repeat it: the backup copy is in the folder shown above.
- After a read the channels are "not yet saved to a file".
- When the radio is connected to the PC do not use the original program at the same
  time (the COM port can be opened by only one program).

FIRMWARE UPDATE (BAJETON 8300)
In the "Bajeton 8300" tab press "⬆ Update firmware…". The window has three steps.
1. Firmware
   - "File on the PC…": choose the firmware file (.anc, e.g.
     BJ8300_V0.12_20251112.anc) or a .zip or .rar archive containing it, even archives
     nested inside each other (like the manufacturer's package: a .rar containing a
     .zip with the .anc).
   - "From the Internet": paste the file's address (.anc, .zip or .rar) and press
     "Download". Share links of a single Google Drive or Dropbox file also work. A
     link to a Google Drive FOLDER cannot be downloaded: open the folder in the
     browser and copy the file's link, or download it and load it from the PC.
     Downloaded firmware is kept in %APPDATA%\GestioneCanaliRadio\firmware.
   - If the archives contain several firmware files, the program asks which one to
     use.
   - Checks on the file: format ("JLUFW" signature of the radio's firmware),
     decryption (the .anc file is encrypted: the program decrypts it like the original
     one and checks that the content is readable), platform the same as the official
     BJ-8300 firmware's (YHD15C8_soundbox), file name, SHA-256 fingerprint of the
     known official firmware. The BJ8300 V0.12 firmware of 12/11/2025 (the latest
     published by Bajeton) is recognized as official. An invalid file cannot be sent;
     a file with warnings (e.g. a different platform) needs an extra confirmation.
2. Radio
   - Choose the cable's port and the radio's state:
     "Works normally" (like the "Update" button of the original program): first of all
     the radio is IDENTIFIED with the Bajeton 8300 programming protocol (the same as
     "Read from radio") and, by default, a copy of its channels and settings is read
     and saved (Bajeton_prima_del_firmware_….dat in copie_radio). If the radio does
     not answer like a Bajeton 8300 the update does NOT start and the radio is not
     touched. Then the radio is put in update mode and receives the firmware.
       "Identify the radio" only does the check, without updating.
     "Does not start" (recovery mode, like the "Click Here If Your Radio Can't Work"
     button): for a radio left without a valid firmware. The radio cannot be
     identified: the program, like the original, waits about 12 seconds for the radio
     to appear in update mode. Press "Start update" and immediately put the radio in
     update mode according to the dealer's instructions (usually by turning it on with
     a key held down, often the PTT: the procedure is not documented).
   - Transfer speed: 115200 baud (default of the original program) or 57600.
3. Confirmation
   - "I confirm that the connected radio is a Bajeton BJ-8300" must always be ticked.
   - When the radio is not identified by the program (recovery mode, or "skip
     automatic identification") you must also type BJ8300 in the box.
During the update a window shows progress and messages. Do not turn off the radio and
do not unplug the cable; use a charged battery. The operation can be interrupted only
until the radio has started to answer. At the end turn the radio off and on again and
check the version at power-on; if channels or settings have changed, write to the
radio the copy saved before the update. If the update is interrupted: turn the radio
off and on and repeat it; if the radio no longer starts, repeat it in recovery mode.
Protocol: that of the manufacturer's program "BinTe ANC Bootloader" V1.1 (BinTalk),
derived from its code: AA 55 packets with CRC16, 9600 baud, command to enter update
mode, switch to 10000 baud and then to the chosen speed, sending of the data requested
by the radio, 5 retries at 2-second intervals. The original program checks neither the
file nor the radio's model: the checks described above are added by this program.
.rar archives (RAR 1.5-5 formats, also "solid") are opened by the program with the
free decoder rardecode (BSD license). Password-protected archives and archives split
into several parts are not supported.

CHANNEL TABLES
- Double click, Enter or F2 to edit a cell; you can also just start typing. Esc
  cancels the edit. On an empty row you start by typing the RX frequency.
- Frequencies in MHz (145.600 or 145,600). The shift is written -0.6, +1.6, +5: the TX
  is computed. For a TX in another band type the TX frequency directly.
- Tones: standard CTCSS tones (67.0 … 254.1) or DCS codes: D023N normal, D023I
  inverted (D023 = normal); empty = OFF. "TX tone" opens the repeater, "RX tone" is
  the tone squelch on receive. The K67 accepts any octal DCS code; the Bajeton the 104
  standard codes (D023 … D754).
- Scan: channel included or not in the scan (now also on the K67).
- Mode (only radios with digital channels): Analog or DMR / Digital. On digital
  channels tones are not used and the radio's digital settings remain.
- Selection: click, Shift+click (range), Ctrl+click (add), Ctrl+A (all).
- Checkmarks (3.9.3): box to the left of each channel (Shift+click ticks a range, the
  space bar the selected rows); the box at the head of the column ticks the visible
  channels, "☑ Select all" / "☐ Deselect all" all the radio's channels. "📻 Forward to
  another radio" and "→ Archive" use the ticked channels or, if there are none, the
  selected ones. Checkmarks follow the channel when you move or edit it; they are not
  saved in the file.
- Buttons and keys: Add; Insert row (Ins); Clear (Del); Delete and compact
  (Shift+Del); Move up/down (Alt+↑ / Alt+↓); Sort (by frequency, name, tone: if you
  selected several channels it sorts only those); Compact (removes the gaps);
  Copy/Cut/Paste (Ctrl+C/X/V); Undo/Redo (Ctrl+Z/Y). Right-clicking on the table opens
  a menu with the same operations.
- When pasting onto occupied positions the program asks whether to overwrite, insert
  moving down, or use only the free positions.
- Bajeton 8300: 15 zones of 64 channels. Choose the zone from the bar above the table,
  "All" to see them together; "Move to zone" moves the selected channels.
- K67 Pro: 640 channels. The radio's frequency ranges are read from the file:
  out-of-range frequencies are highlighted in red.
- Bulk edit (4.11): «✎ Bulk edit…» (also from the right click) changes together, in
  the ticked channels or, if there are none, in the selected ones: power, bandwidth,
  scan, TX tone, RX tone (OFF removes the tone), shift and, where the radio allows it,
  transmission (receive only). The items left on «do not change» stay as they are in
  every channel; subtones are not put on digital channels. Tones and shift are checked
  before any channel is changed; Ctrl+Z undoes the whole operation.

ZONE NAMES (4.11)
Instead of «Zone 1», «Zone 2»… each zone can be given a name, as in the manufacturer's
programs. The «✎ Zone names…» button (or a double click on a zone of the bar) opens
the list of zones with their names; the zone bar and the status line show «number ·
name». The names are in the radio's memory: they are read and written by cable
together with the channels and saved in the .img file.
- Radtel RT-950 Pro, Bajeton BJ-9000, Hiroyasu HI-UV850 Pro (firmware up to 0.23: 15
  zones; from 0.24: 10 zones) and Radtel RT-950 (15 zones): up to 12 characters;
  letters without accents, digits, symbols and Chinese characters (GB2312, 2 bytes
  each), as in the manufacturer's programs RT-950PRO_CPS v1.2.0-v1.3.3, BJ-9000_CPS
  v1.3.3 and BT-9000_CPS v1.3.0 (area 0xC000, 16 bytes per zone).
- Radtel RT-920 (firmware V0.17 and later, 10 zones): up to 10 characters, as CHIRP's
  driver (the manufacturer's program v1.2.4 allows 12; area 0xC800).
- Radtel RT-910 / Bajeton BJ-7700 without Bluetooth (15 zones): up to 12 characters
  without accents, as the manufacturer's program RT910_EnCPS v1.0.3 (area 0xA200).
- DMR radios Baofeng RD-5R, DM-1801 and DM-32UV: the existing zones are renamed (up to
  16 characters); every zone must have a name.
- Safety: for RT-950 Pro, BJ-9000, HI-UV850 Pro, RT-950 and RT-910 the names area is
  written only if the names change, and it is first read back from the radio: if it
  contains data that are not names (firmware without zone names) nothing is written
  and a message appears. An empty name leaves the zone as the radio shows it. For the
  RT-920 the area is among those always written, as CHIRP does.
- .img files of the RT-950 saved before 4.11 do not contain the names: read the radio
  again to see them. If the radio does not answer the reading of the names (old
  firmware) the file stays without names and everything else works as before.

COPYING BETWEEN THE TWO RADIOS
Copy in the first tab and Paste in the other (since 3.9.3 "Copy to…" has become "📻
Forward to another radio", which writes directly to the connected radio: see
"FORWARDING TO ANOTHER RADIO") adapts the channels with the converter's logic and
shows the warnings:
- names: max 16 characters on the K67, 12 on the Bajeton (abbreviations M. S. D. and
  final number kept, e.g. "CAMPOLUNGHINO 3" → "CAMPOLUNGH 3");
- power: the Bajeton's Medium becomes High on the K67;
- DCS tones: transferred if the destination radio has that code, otherwise OFF with a
  warning;
- frequencies outside the K67's ranges.
In the insert window choose the zone (Bajeton), the starting position and whether to
use only free positions or overwrite.

FORWARDING TO ANOTHER RADIO (3.9.3)
"📻 Forward to another radio" (in each radio's tab and in the right-click menu) writes
the chosen channels directly to another radio connected with the cable:
1) tick the channels (box on the left; "☑ Select all" for all the radio's channels):
   if you ticked none, those selected with a click are used;
2) choose make and model of the destination radio from the two drop-down menus (the
   models are divided by type) and where to put the channels: in the free positions
   (the channels already in the radio stay) or in place of all the radio's channels;
3) confirm that the model is the right one and that the radio is connected to the
   cable and switched on;
4) compatibility check, as for the repeater archive: frequencies within the radio's
   ranges, no amateur channel on a PMR446 / GMRS set (yellow warning if the radio
   accepts those frequencies anyway), no DMR channel on an analog-only radio. You can
   cancel, choose another radio or send only the compatible channels;
5) choose the cable's port and press "Forward and write". The program reads the radio
   and saves a backup copy of it ("copie_radio" folder, file
   "..._prima_dell_inoltro_..."), adapts the channels to the radio (names, characters,
   tones, power levels, receive-only or digital channels, locked positions such as
   fixed GMRS channels), writes them and reads the radio again to verify them.
The radio's settings (menus, VFO, keys…) stay those read from the radio: only the
channels change. If free positions are missing or no channel can be used, the program
stops before writing and nothing is written to the radio. At the end the window shows
the positions used and the adaptations; if the destination radio's tab was not open,
"Show the radio's channels" opens it with the channels as they now are in the radio.

WHAT IS PRESERVED
The program changes only what you change. A file opened and saved without changes
stays identical byte for byte. Data the program does not interpret (other bytes of the
K67 record, the signaling/PTT ID/busy lock/etc. fields of the Bajeton) stay unchanged
and follow the channel when you move or copy it within the same radio. The radios'
general settings change only with "⚙ Settings…" (and only the items you modify). K67:
when you add or delete channels, the zone lists, the A/B channels and the emergency
channel are updated as the original program does (zones are not edited from here).

FIX OF AN ERROR IN VERSION 1.0 (K67 Pro)
Analyzing the original program it turned out that the .xlc file has two bit tables per
channel ("position occupied" and "in scan"). Version 1.0 used wrong tables: a channel
added in a position that was EMPTY could be invisible to the radio and to the original
program (edits and deletions of existing channels were correct). If you saved .xlc
files with 1.0 adding channels in empty positions, open them with this version: the
affected positions are reported and it is enough to insert those channels again (or
repeat the addition).

REPEATER ARCHIVE
- It is shared by all radios and saves itself, on the PC, in:
  %APPDATA%\GestioneCanaliRadio\archivio_ponti.json (backup copy: .bak)
- "Import…": from the Internet (preset address https://www.ik2ane.it/pontixls.xls,
  editable; the addresses used are remembered) or from .xls, .xlsx, .csv files. It
  recognizes the IK2ANE list ("ponti" sheet), CHIRP CSVs, files exported by this
  program and generic sheets with headers such as Frequency, Shift, Tone, Name,
  Location, Region, Province, Type, Network.
- Irregular values interpreted with common sense and reported (yellow rows with ⚠):
    "+5.0MHz", "-600 kHz"         → normal shifts
    "+1.362,5 MHz"                → 1.3625 MHz (reported)
    "79,7" "123"                  → 79.7 / 123.0
    "77.0-141.3" "110.9/162.2 loc"→ first tone used, the others shown in the warning
    "82.2" (non-standard)         → 82.5, reported
    "CC1" (DMR color code)        → no tone, noted in the notes
    "DCS023", "1750", "DG-ID:10"  → noted/reported
    "input" / "output"            → simplex, reported
  The original value stays visible in the detail panel. Rows without a valid frequency
  (e.g. the 9999999 placeholders and the final text rows) cannot be imported: they are
  listed in the window, not silently discarded.
- The legend colors are also read from the IK2ANE file: repeaters no longer active,
  temporarily out of service, not H24, non-regional tone, non-standard shift.
- Filters (in import, in export and in the archive): band (VHF/UHF/Other), type
  (Analog, EchoLink, SvxLink, DMR, C4FM, D-Star, NXDN, Multimode, HotSpot,
  Transponder, Winlink), status, region, province, network, free text, only rows with
  warnings; plus the per-row checkmark. In import the filters start from "only
  repeaters usable in analog, excluding inactive ones": you can change them.
- Channel name: a template of your choice with {LOC} {SIGLA} {NOMINATIVO} {PROV}
  (location, code, call sign, province; e.g. "{NOMINATIVO} {LOC}" → "IR0XX M.ALTO").
  "Regenerate names…" applies it again.
- Repeaters already present (same frequency, TX, location and code): you can add only
  the new ones, update those present (the name you gave stays) or replace everything.
- Tick the repeaters you want to put in the radio: box to the left of each row (the
  space bar ticks the selected rows), or "☑ Select all" and "☐ Deselect all", which
  apply to the repeaters visible with the current filters. Checkmarks stay saved in
  the archive, also when the program is closed.
- "📻 Forward to the radio" writes the ticked repeaters to the radio (if there are
  none, those selected with a click):
    · if a radio has already been chosen (the one shown in the blue "Destination
      radio" bar, i.e. the last used or the last radio tab opened) a window appears
      with the model and the request for confirmation ("Confirm and write", or "Choose
      another radio…");
    · otherwise the list of all compatible radios opens, with search: divided by make
      (Baofeng, Bajeton) and by type, with each model listed on its own in
      alphabetical order (in brackets the handling used, e.g. "UV-5RA (handled as:
      Baofeng UV-5R)", or the version, if the radio has more than one).
  Before writing, the program checks that the repeaters are compatible with the chosen
  radio:
    · receive and transmit frequencies within the radio's ranges;
    · no amateur repeater on a PMR446 / licence-free set (only 446.0-446.2 MHz) or
      GMRS / FRS set (only 462.55-467.725 MHz);
    · no digital-only repeater (DMR, C4FM, D-Star, NXDN) on an analog-only radio; on
      DMR radios (DM-32UV, DM-1801 Pro, DM-5000) DMR-only repeaters become DMR
      channels.
  Exception: some radios sold as PMR446 / licence-free or GMRS also accept amateur
  frequencies (the driver's ranges are those of the manufacturer's program, e.g.
  BF-T17 PMR446 400-480 MHz). For repeaters within those ranges a yellow warning
  appears with "Write the N repeaters anyway": writing is allowed (also from the
  radio's tab, pasting or inserting the repeaters). Respect the regulations:
  transmitting on amateur frequencies requires a licence, and a type-approved PMR446
  set must not be used outside its channels.
  If there are no problems the repeaters are sent; otherwise a warning appears ("You
  chose a device that is not compatible with the data you are trying to send to the
  radio") with the list of problems, and nothing is written to the radio: you can
  cancel, choose another radio or, if part of the repeaters is compatible, send only
  that part.
  Then the usual insert window opens (starting position, only free positions or
  overwrite, adaptations for the radio); if the radio has not been read yet the
  program offers to read it via cable or to open one of its files. "Change radio…" in
  the blue bar changes the destination.
- "Copy" copies the ticked (or selected) repeaters to paste them into a radio
  (Ctrl+V).
- "🗑 Delete" (3.9.3) removes from the archive the ticked repeaters, also those hidden
  by the filters (the confirmation says how many), or, if there are none, those
  selected with a click; the Del key deletes the selected rows. "🗑 Delete all" empties
  the archive. Both ask for confirmation and can be undone with ↶ (Ctrl+Z) as long as
  the program stays open; to reload the IK2ANE list use "⬇ Import…".
- "Mark as checked" removes the warnings after checking (they stay in the notes).

CONVERTER AND UNIVERSAL FORMATS (3.7)
- "🔁 Convert" tab: 1) choose the source file or an open tab; 2) choose the destination
  format (search by name); 3) "Convert and save…". After the conversion the list shows
  all the adaptations (shortened names, power levels, unavailable tones, channels out
  of range or excluded) and "Open in the radio's tab" opens the file produced.
- Source files: .xlc (K67), .dat (Bajeton, v1.0.8 or v1.0.9), .img images of any
  compatible radio (also saved by CHIRP: the model is recognized from the file's
  data), CHIRP CSV (also with comment rows), Excel or CSV tables (exported from here,
  from the repeater archive or written by hand: a column with the frequency is needed,
  e.g. «RX (MHz)», «Frequenza» or «Frequency»; optional name, TX, shift, tones, power,
  bandwidth, scan, RX only, digital).
- Destinations: CHIRP CSV (universal format, it opens with CHIRP for any radio), Excel
  .xlsx, CSV for Excel, K67 .xlc file, Bajeton .dat for v1.0.8 or v1.0.9 of BT-11_CPS,
  .img image of each of the radios handled with the drivers. Channels stay in the same
  position if the radio has it (or "compact the channels"); the extra ones go into the
  first free positions, the others are excluded and reported. The locked positions of
  some radios (e.g. the fixed GMRS channels of the GM-15 Pro) stay those of the radio.
- For a radio's .img image you need an image of that same radio, i.e. the complete
  copy of its memory (the tab opened after "Read from radio" or "Open…", or an .img
  file saved earlier from here or from CHIRP; since 3.8 also with "📻 Read the
  connected radio now…" directly from the converter): the image contains the radio's
  settings and calibration, which cannot be made up, and writing an "empty" one would
  damage the radio. For the K67 and the Bajeton you can also start from the default
  settings of the manufacturers' programs.
- "📥 Import…" (each radio's tab) and "Export…" → "🔁 For another radio…" use the same
  converter.

RADIO IDENTIFICATION (3.8)
- "🔎 Identify" tab: choose the cable's port (or "USB" for DMR radios with a direct USB
  cable: RD-5R, DM-1801, DM-1701) and press "Identify the radio". You can narrow the
  search by make or type (analog / DMR): it is faster.
- The program tries the READ protocols one after the other (first K67 Pro and Bajeton
  BJ-8300, then the driver radios, starting with those with an open tab). Models that
  start the connection in the same way are tried only once (38 attempts for the 100
  radios via cable; since 4.1, 60 attempts for all radios via cable). When a radio
  answers it is read completely, as with "Read from radio", and a copy of the read is
  saved in the copies folder (copie_radio).
- The model is recognized from the content of the memory, as CHIRP does with files.
  Many radios, however, use the same protocol and the same memory without writing
  their own name anywhere (e.g. the radios of the UV-17Pro family, the PMRs of the
  BF-888S family): in that case the program says so ("Model cannot be told apart via
  cable") and lets you choose the right model before opening the channels.
- Shown: make and model, type (analog FM or DMR, PMR446, GMRS), frequency ranges,
  number of memories, connection used, firmware or identifier reported by the radio
  (e.g. UV-5R "BFB297", BJ-8300 "BT-11U V1.00", DM-32UV firmware, K67 "5RH-PRO" or
  "BF-K6"), text sent by the radio during the connection, channels present; for RD-5R,
  DM-1801 and DM-1701 also DMR ID, radio name, date of the last programming and
  (DM-1701) version of the program that wrote it. The serial number: none of these
  radios reports it with the programming protocol (it is only on the label).
- "Open the channels in the radio's tab": as after "Read from radio".
- Times (4.3): with no radio connected the full search takes about 50 seconds (81
  attempts; fewer if you narrow the search by make or type); first the radios already
  recognized in the past are tried (the last 24), then those with an open tab, then
  the others. A radio that answers is found as soon as its turn comes and then read.
- If a radio answers but the read does not succeed (e.g. password, different model)
  the answers are listed in the details. If the radio stays stuck in programming mode,
  turn it off and on again.

AUTOMATIC IDENTIFICATION (4.0 - 4.7)
- In the "🔎 Identify" tab press "🔄 Enable automatic identification". From then on,
  while the program is open, when you connect the programming cable (or a DMR radio
  via USB) the radio is searched for by itself, with the same READ-only commands as
  "Identify the radio": nothing is written to the radio.
- It works in any tab of the program. The box "Identifying radio. Please wait." (with
  "Stop") appears at the bottom only when a radio connected to the cable really
  answers, and disappears when the radio is recognized or the search ends. Since 4.4
  line noise (0x00, 0xFF and similar, typical of a cable with no radio or with the
  radio off) and the echo of the commands sent, even if it arrives late, are not
  enough: at least 4 real bytes or two distinct answers are needed. With several
  cables the box shows only the ports with a radio that answers.
- When the radio is recognized its data appear (also in a window) and its tab opens
  with the channels read; if the tab had unsaved changes the program asks before
  replacing them.
- Since 4.2, after recognition the search STOPS (the function stays active): to search
  for another radio on the same cable press the yellow button "🔎 Identify radio" at
  the top right, next to "? Guide" (since 4.4; it is grey and cannot be pressed if
  automatic identification is off; with many tabs open it shrinks to just the
  magnifier). A cable connected to the PC later (even the same one, unplugged and
  plugged in again) is searched by itself.
- Since 4.3 the program LISTENS CONTINUOUSLY on all the ports of the connected cables,
  each on its own and all together: a radio turned off or with the volume at minimum
  does not stop the search, which starts again immediately (without the box) as long
  as the cable stays connected. So you can connect the cable and turn on the radio
  afterwards: it is recognized as soon as it answers. A radio that answers but is not
  among those handled is tried again every 30 seconds.
- Several radios connected to different cables (e.g. COM6 and COM7) are searched at
  the same time: for each one the data appear and the tab opens; if the tab is already
  open the notice "Radio already identified!! Radio tab already open" appears (with
  several radios "Radios already identified!! Radio tabs already open"). After
  recognition only that radio's port stops: the others keep listening.
- Recognized radios are remembered (also after restarting): later searches try them
  first, and during the search they are tried again every 8 attempts, so a radio
  already used (e.g. K67 Pro, Bajeton 8300, BJ-9000) is recognized in a few seconds.
- Only the ports of programming cables are searched (USB-serial adapters CH340,
  Prolific, Silicon Labs, FTDI…), never Bluetooth ports, modems or the system serial
  ports (COM1, COM2).
- An automatic search in progress stops by itself when you ask for another operation
  (read, write, firmware, forwarding or manual identification).
- The choice stays saved also after closing and restarting the program. To stop using
  it go back to the "🔎 Identify" tab and press "⏹ Disable automatic identification".
- (4.7) Before trying the models the program listens to the port for 1 second (once a
  minute per port and speed). A radio in firmware update mode sends periodic messages
  by itself: those bytes do not count as an answer, so the search ends soon and the
  Identify tab warns that the radio is probably in update mode (turn it off and on
  normally, or use the Firmware tab).
- (4.7) Order of the attempts: radios already recognized, those with an open tab, then
  the most common (K67 Pro, BJ-8300, BJ-7800 / RT-920, BJ-7700 / RT-900, BJ-9000 /
  RT-950 Pro, TD-H8, UV-17 / UV-17Pro, UV-K5, UV-5R, BF-888S), then the others.

DM-1701 USB DRIVER (3.8)
- The DM-1701 (and the Retevis RT84) connects via USB in DFU mode (device 0483:DF11)
  and needs a driver. Two possibilities:
  1. the manufacturer's driver (STTub30), "DM-1701 USB Driver" folder of the "DM-1701
     CPS" package: in the DM-1701's "Read from radio" window the "Install the USB
     driver…" button asks for the installer (dpinst_amd64.exe, or the .inf file) and
     starts it with Windows authorization (with an .inf it uses "pnputil /add-driver …
     /install", Windows 10 and 11);
  2. Windows' generic WinUSB driver, installed with Zadig (https://zadig.akeo.ie,
     Options → List All Devices, device 0483 DF11, WinUSB driver): the same one used
     by dmrconfig and qdmr. After this operation the manufacturer's program no longer
     sees the radio until its driver is reinstalled.
- The program uses whichever is installed by itself; the window shows whether the
  radio is connected and with which driver.
- A Windows driver cannot be included in the program or redistributed: that is why the
  official one (or WinUSB, which is part of Windows) is used.

BTECH DMR-6X2: GUIDED FIRMWARE UPDATE (3.8)
- DMR-6X2 (firmware 2.21) and DMR-6X2 PRO (firmware 1.21) are DMR radios of the BTECH
  brand (BaofengTech, United States). The firmware is installed with the official
  "Firmware_Update" program of the BTECH package (menu Tool → Firmware Upgrade of the
  CPS, or C:\DMR_6X2_2.21\Update\Firmware_Update.exe), with the radio in update mode:
  off, hold PTT and Alarm (the orange key) and turn it on (the LED flashes red); COM
  port of the "USB Virtual Com Port Driver", 921600 baud, Duplex, "Write". After the
  firmware (and the icons, PTT + PF2 at power-on) a reset must be done (PTT + PF1 at
  power-on) and the codeplug saved beforehand written back: the update erases the
  programming. Source: "STOP and README FIRST.pdf" of the official packages
  DMR-6X2-221b and DMR-6X2-PRO-121e (https://baofengtech.com/software/).
- In the gallery, radio card → "🧭 Guided update…": choose the .spi file and the
  program checks that the .spi, .CDI and .CDD files are consistent and complete, which
  radio they are for (DMR-6X2 or PRO: the firmware must not be swapped), what kind of
  update it is (firmware, icons, APRS board) and the version; it shows the right
  procedure and starts the official program (also as administrator).
- The firmware is written by the BTECH program: its protocol is not published and the
  program is compiled, so it was not possible to compare it with another
  implementation; a mistake could make the radio unusable.

SEARCH FOR NON-COMPATIBLE RADIOS (3.7)
Search in forums and enthusiasts' sites (CHIRP, RadioReference, miklor.com, RigPix,
GitHub) for programs or workarounds for the non-compatible radios:
- UV-8D / BF-UV8: CHIRP does not handle them (reports #1225, still open, and #4519):
  the radio does not indicate which channels are empty and a 2014 test driver gave
  written channels that the radio did not show; it can be programmed only with the
  manufacturer's program for the UV-8 (in Chinese). Not handled here: without that
  program the result could not be verified.
- DM-5R (Tier I): dmrconfig handles the TD-5R but expressly says "not DM-5R"; the
  radio uses a cable different from the other Baofengs and a native program. Not
  handled (the RD-5R, a different radio, is handled). To handle it would require
  (3.8): its manufacturer's program (written in C++Builder, so machine code: it is
  studied with a disassembler such as Ghidra or IDR, much more slowly than a .NET
  program) and above all a recording of the dialogue between that program and a real
  DM-5R (read and write) made with a serial port monitor, together with the file saved
  by the program and the radio's specific cable.
- DM-1702 / DM-1703: free tools exist (MD1702-tools) that read and write the memory,
  but their own authors warn that with the L05 firmware and the MD1706-V2 loader they
  made radios unusable: not handled, out of caution.
- DM-V1: the manufacturer's own program, micro-USB cable with the converter inside the
  radio; no free program handles it.
- PMR446 without a published program (BF-T3, BF-T6…T57, BF-V1…V6A, BF-33C, BF-358…):
  for some similar radios CHIRP users have used the BF-888 driver with partial success
  (e.g. BF-M4, report #7215, later added to CHIRP). It is not a safe workaround:
  without the manufacturer's program you cannot know whether the memory is the same,
  and writing a different memory can lock up the radio.
- 5RHam, BJ-98 Plus, M20D: no programs or technical information were found.

EXPORT
From the archive (with filters and checkmarks) or from a radio's channels (all or
selected):
- Excel .xlsx and Excel 97-2003 .xls (first row frozen, rows with warnings in yellow);
- CSV for Italian Excel (";" separator and decimal comma);
- CSV for CHIRP: standard CHIRP columns. Power is written in watts (High 5.0W, Medium

HOW IT WAS VERIFIED
The code of the two original programs was decompiled and run on simulated radios, side
by side with this program:
- writing: radio memory identical byte for byte and same sequence of commands (K67: 17
  commands, 49,152 bytes; Bajeton: 505 commands, 49,984 bytes), both with the example
  files and with modified files (moves, deletions, new channels, DCS);
- reading: file identical to the one saved by the original program (apart from the
  date); Bajeton: all 15,600 fields of the .dat equal;
- the original program reopens and re-saves this program's files without other
  changes;
- wrong password, radio off, different band, data refused, interruptions, backup copy
  and verification are tested with automatic tests.
IT HAS NOT BEEN POSSIBLE TO TEST IT WITH REAL RADIOS. At the first try: start from a
read, save it to a file and keep it aside; then try writing.
Firmware update (2.1): the ORIGINAL code of the "BinTe ANC Bootloader" program (loaded
directly from its executable) and this program were connected to the same simulated
Bajeton in 10 situations (update at 115200 and at 57600 baud, recovery mode, files of
any length, lost answers, wrong CRCs, lost speed change, radio off, real V0.12
firmware with 700 KB of data): in all cases the simulated radio received the same
packets, at the same speeds and with the same data, and the outcomes are identical
(same retries, same errors). The Windows executable was also tested under Wine with
real serial ports (pseudo-terminals): update and recovery completed, speed changes
correct. The firmware update, too, has NOT been tested with a real radio: the radio's
behaviour is reconstructed from what the original program expects.

New in 3.0, same checks:

  reading of the channels from CHIRP's test images (all channels equal), up to 18

LIMITATIONS
- The protocols and formats are proprietary and reconstructed from the original
  programs: always keep the backup copies.
- The zones of the K67, the DM-32UV, the DR-1801UV and the USB DMR radios are not
  edited from here (they are only kept consistent); for DMR contacts, groups and
  settings use the manufacturer's program.
- Settings: the descriptions of the CHIRP radios' items are written starting from the
  English name of the item (many drivers use different names for the same function):
  the original name is always shown at the end of the description.
- At least some K67 Pros identify themselves as "BF-K6" (verified with a real radio,
  3.7): writing starts if the last radio read was of the same model, as in the
  original program (with the backup copy active the read happens by itself).
- Identification: some different radios use the same protocol and the same memory
  without indicating their model: in that case the program offers the possible models
  and the choice is yours. A radio that answers a protocol of another family might
  stay in programming mode: turn it off and on again.
- Downloading from the Internet uses the direct connection (not the system proxy).
- Radios handled with the CHIRP drivers: CHIRP's limitations for that model apply
  (e.g. BJ-7800 written for firmware V0.15P; if the radio has a more recent firmware
  and does not answer as expected, the read stops without changing the radio).
- Firmware: the procedure to put a locked-up radio into update mode is not documented
  by the manufacturer. Automatic identification recognizes the radios that use the
  Bajeton 8300 (BT-11) programming protocol: a different radio with the same protocol
  could not be told apart, which is why your confirmation is also needed.

REBUILDING FROM SOURCE (optional)
Go 1.22 or later is needed. In the "sorgenti" folder:
      go build -mod=vendor -trimpath -ldflags "-H=windowsgui -s -w -X main.buildDate=YYYY-MM-DDTHH:MM" -o "IU0VYT Flash.exe" .
(buildDate is the build date shown in the Info tab, e.g. 2026-10-20T21:45.)
Icon and properties of the .exe file (name, version) are in res/risorse.rc, compiled
into rsrc_windows_amd64.syso (the command is written at the top of the .rc file).
(The libraries are already included in the vendor folder; the icon is in
rsrc_windows_amd64.syso.)
On Linux "go test -mod=vendor ." runs the automatic tests on the example files in
testdata and with the simulated radios. The "verifica" folder contains the programs
for comparison with the original code (see verifica/LEGGIMI_VERIFICA.txt).
The tests on importing the IK2ANE repeater list need the file testdata/pontixls.xls
(not included: third-party data, downloadable from www.ik2ane.it).
