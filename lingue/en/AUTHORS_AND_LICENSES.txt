QUANSHENG UV-K5 FIRMWARE UPDATE (4.1)
The format of Quansheng's .bin files and the protocol of the UV-K5 loader are
documented by the free programs k5prog (Copyright 2023 Jacek Lipkowski SQ5BPF, GNU GPL
v3, https://github.com/sq5bpf/k5prog) and uvtools (egzumer,
https://github.com/egzumer/uvtools). fwk5.go is written from scratch on the basis of
that documentation, for interoperability; no code of those programs is included in the
package. verifica/k5/k5ref.js, used only for the tests, loads the uvtools code from
the folder indicated by whoever runs the verification. Thanks to SQ5BPF and to
egzumer.

TIDRADIO TD-H3 / TD-H8 AND RADTEL RT-730 FIRMWARE UPDATE (4.3)
The loader protocol is documented by nicsure in the TD-H3-Engineering project
(https://github.com/nicsure/TD-H3-Engineering, firmware_flash_protocol.txt, with the
port capture of the manufacturer's program) and used by his program TID Station; the
same 36-byte handshake is in the manufacturer's programs «H8_IAP» (TIDRADIO) and
«RT730 Update tool» (Radtel). fwtdh.go is written from scratch on the basis of that
documentation, for interoperability; no code of those programs is included in the
package. Thanks to nicsure.

FIRMWARE UPDATE WITH THE 7.x LOADER (UV-K5 V3, UV-K1, RA79 V3) (4.4)
The protocol is described and used by the free programs quansheng_toolkit (Copyright
2026 knoinok, Apache 2.0 license, https://github.com/knoinok/quansheng_toolkit,
kradio/dfu.py) and Multi-UVTools (spm81, https://github.com/armel/Multi-UVTools,
js/flash-k1.js). fwk5.go (k5v3Update) is written from scratch on the basis of that
documentation; no code of those programs is included in the package.

RETEVIS RA89 (4.4) AND RT85 (4.5) FIRMWARE UPDATE
Protocol derived, for interoperability, from Retevis's programs «RA89-update-software»
(«TH8600-UpDAta Soft» 2.3) and «RT85 10W_5W_UpData» («TH8600-UpDAta Soft» 2.1,
retevis.com); the programs are not included in the package. verifica/ra89, used only
for the tests, loads the executable indicated by whoever runs the verification.

ZONE NAMES (4.11)
The format of the zone names is derived, for interoperability, from the code of the
manufacturer's programs: Radtel RT-950PRO_CPS v1.2.0-v1.3.3 and Bajeton BJ-9000_CPS
v1.3.3 (RT-950 Pro, BJ-9000, HI-UV850 Pro), RT-950_EnCPS «BT-9000_CPS» v1.3.0
(RT-950), RT-920_EnCPS v1.2.4 (RT-920) and RT910_EnCPS v1.0.3 (RT-910 without
Bluetooth), radtels.com and bajeton.cn; for the RT-920 also from CHIRP's driver
radtel_rt900.py (Fred Trimble, GNU GPL, see above). No manufacturer's program is
included.
The idea of naming the zones and the bulk editing of channels come from the «RT-950 /
950 Pro Editor» program by Jorge De La Cruz KK4OXN
(https://github.com/cruzerdlc/RT-950-950Pro-Editor, MIT license): the repository
publishes only documents and compiled programs, not the source code, and no code was
taken from it; the functions are rewritten from scratch in IU0VYT Flash.

.BTU FIRMWARE (4.8)
The .BTU firmware of the Radtel RT-910 and RT-900 without Bluetooth and the Bajeton
BJ-7700 without Bluetooth is sent with the protocol of the «Radtel Bootload Tools»
program (Radtel, radtels.com), derived from its code for interoperability: it is the
same KDH V1.0 loader as the Baofeng UV-5RM (bfkdh.go), with the «PROGRAMBT80U»
handshake. The firmware (Radtel radtels.com, Bajeton bajeton.com) is recognized only
by its SHA-256 fingerprint; for the RT-900 the manufacturer's programs «RT900_512 CPS»
v1.0.0 and v1.0.2 (512 and 999 channels) were also compared. No program or firmware is
included in the package.

The .kdhx firmware of the Radtel RT-470 / RT-495 / RT-630 uses the same protocol as
the «Bootloader Pro» of the UV-25 Plus (fwkdhx.go), with the JJCC platform indicated
by Radtel's program «New RT470 serial Bootloader Pro».
The changes compared with the original CHIRP files (rewriting in Go, channels only,

SETTINGS DERIVED FROM CHIRP (since 3.6)
---------------------------------------
The settings tables of the radios handled with the CHIRP drivers
(sorgenti/settings_chirp.json) are derived by having CHIRP's code (GNU GPL, authors as
above) read and write every item (sorgenti/verifica/chirp/chirpsettings.py): they
contain the position of the data in memory, the allowed values and the English names
of the CHIRP items.
Since 3.7 the CHIRP CSV format (columns of the generic_csv driver) is read and written
by the converter and compared with CHIRP's code (sorgenti/verifica/chirp/csvcheck.py,
which is not included in the program).

  RB27, TH-888S and BF-777S = BF-888 and, since 3.4, the 77 equivalent models of the

  (P52UV), #10388 (GMRS-9R), #11280 (UV-E70) and #11696 (BF-9700 and BF-S56 Max:

  with the UV-3R driver) and, since 3.5, #11119 (K5 Plus derived from the UV-5RM, for
  the firmware family). For the models reported by users the compatibility is marked
  as experimental.
- Official BTECH instructions for updating the DMR-6X2 and the DMR-6X2 PRO («STOP and
  README FIRST.pdf» of the packages DMR-6X2-221b and DMR-6X2-PRO-121e,
  https://baofengtech.com/software/), summarized in the guided procedure (since 3.8);
  the structure of the .spi/.CDI/.CDD files is derived from the package files. BTECH
  programs, drivers and firmware are not included.
- Zadig (https://zadig.akeo.ie, GPL) is only mentioned as a tool to install the WinUSB
  driver of the DM-1701: it is not included.
- IK2ANE's list of Italian repeaters (https://www.ik2ane.it): it is not included in
  the package; the program downloads it from IK2ANE's site when you ask. The data
  remain IK2ANE's, who makes them available to everyone free of charge.
