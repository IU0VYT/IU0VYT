4.18.0 (2026/11/11)
-------------------
- Kenwood TK-2140과 TK-3140(drv_kwtk140.go, 신규; CHIRP의 tk3140.py: TK-2140K, TK-3140K, TK-3140K2, TK-3140K3) 및 Kenwood TK-280과 TK-380(drv_kwtk280.go, 신규; CHIRP의 tk280.py): 48바이트 위치 250개가 존 또는 그룹으로 나뉩니다. 프로그램의 목록은 물리적 위치의 목록입니다. 수정한 채널은 자기 존에 자기 번호로 남고, 새 채널은 바로 앞 채널의 존에 비어 있는 첫 번호로 들어갑니다. 위치 표는 CHIRP처럼 다시 만듭니다.
- CHIRP 비교 도구(verifica/chirp/chirpref.py): CHIRP에서 존마다 «하위 무전기»를 갖는 기종을 처리합니다. 여섯 모델 모두 읽기, 15개 수정, 메모리 구조, 주고받는 바이트, 최종 메모리가 CHIRP와 동일합니다. 설정: 클래스 6개 추가(총 314개). TK-280/380의 그룹별 750개 항목은 포함하지 않습니다.
- fagci의 R3b0rn 펌웨어를 넣은 Quansheng UV-K5 / UV-K6(drv_fagci.go, 신규), 펌웨어 소스에서: 설정, VFO, 프리셋 40개는 0x0000-0x052E. 23바이트 채널은 EEPROM 끝에서부터 거꾸로. EEPROM 종류는 첫 바이트의 하위 3비트(8~256 KiB: 채널 298, 654, 678 또는 1024개). 32비트 주소, 8바이트 단위 쓰기, 38400 보. 채널 영역만 씁니다. 거부하는 경우: 32비트 읽기에 응답하지 않는 펌웨어, 프리셋 수가 40이 아닌 경우, 준비되지 않은 메모리, 크기가 다른 메모리. 레코드는 펌웨어의 구조체를 컴파일해서도 확인했습니다. 펌웨어와 함께 공개된 CHIRP 드라이버와의 의도적인 차이: 송신 주파수를 항상 그대로 쓰고, 이름은 9자입니다.
- Radtel RT-330과 RT-400(drv_jc8810.go), 제조사 프로그램(«Radio CPS»와 «JJCC-7700 CPS»)에서 알아냈으며, 둘 다 MML JC-8810 계열의 프로토콜과 채널 레코드를 사용합니다. RT-330: 핸드셰이크 문자열 «PROGRAMYF68U», 115200 보, 채널 512개, 100-520 MHz. RT-400: 핸드셰이크 문자열 «PROGRAMJC81U»(RT-470과 같음), 57600 보, 채널 256개, 18-1000 MHz. 제조사 프로그램은 식별자를 확인하지 않으므로, 이 탭은 같은 핸드셰이크 문자열을 쓰는 다른 모델의 식별자를 거부합니다. 가상 무전기로만 확인했습니다.
- 카탈로그(catalog_418.go, 신규): 항목 4개, 그리고 UV-K5에 R3b0rn 탭. 집계: 무전기 498개, 설정 지원 427개, 갤러리 552개. 번역: 새 텍스트 29개.
- 이 버전에서 하지 않은 것: Kenwood TK-2180 / TK-3180(CHIRP에서는 추가나 삭제를 할 때마다 메모리 전체가 이동합니다), Radtel RT-871A, RT-1000 Pro, RT-4D, RT-6D, RT-5D(영역이나 레코드가 이미 지원하는 것과 다릅니다).

- 카탈로그: 무전기 494, 설정 지원 425, 갤러리 548, 브랜드 47. 설정: 새 클래스 17개. 번역: 새 텍스트 13개. 테스트: 새 Kenwood 세 계열의 모의 무전기, 60 / 60G 시리즈의 CHIRP 비교.

4.13.1 (2026/11/09)
-------------------
- IJV V6 펌웨어(drv_ijv6.go, 신규): 탭 «Quansheng UV-K5 V3 / UV-K1(IJV V6 펌웨어)». V6 데이터 링크(DTR와 RTS 낮음, CRC32가 붙은 «A5 5A» 요청, 12바이트 «5A A5» 응답): 정보와 버전, 예고한 요청 수로 열기, 256바이트 읽기, 256바이트 페이지를 4 KiB 섹터 단위로 확정, 종료와 재시작. 메모리는 V5와 같습니다(뱅크 n은 0x020000 + n·0x4000, 현재 뱅크는 «CFG5»에서 읽고 쓰기 전에 다시 읽음). 바뀐 섹터만 쓰고 섹터마다 다시 읽어 비교합니다. 보정값, 라이선스, 무전기가 스스로 관리하는 영역은 무전기의 내용 그대로 둡니다.
- 무전기가 V6 데이터 링크에만 응답하면 다른 IJV 탭이 V6 탭을 안내합니다.
- 설정: V6는 V5의 표를 사용합니다. 카탈로그와 UV-K5 펌웨어: V6 탭 추가.
- 번역: 새로 추가되거나 바뀐 텍스트 23개. 테스트: 모의 V6 무전기(읽기, 바뀐 섹터만 쓰기, 바뀐 뱅크, 거부된 설정, 잘못된 탭).

4.13.0 (2026/11/09)
-------------------
- Quansheng UV-K5 / UV-K5 V3 / UV-K1용 IJV 펌웨어(drv_ijv.go, 새 파일): 탭 4개, 200채널 V3
  (0x0500, 8 KiB 이미지), 999채널 V3 X(0x2000-0x9FFF), V4와 V5(무전기에서 선택한 뱅크의
  500채널, 24 KiB 이미지: 고정 영역 0x0000-0x1FFF와 뱅크 0x2000-0x5FFF). 32바이트 채널 레코드,
  그룹, AGC, 컴팬더, 스크램블러, 선택 호출, TX 잠금, 통화 중 잠금 유지. 연결: V3는 UV-K5 순정
  프로토콜, V4와 FW5는 IJV 평문 프로토콜(응답이 없으면 순정), FW5는 물리 읽기/쓰기(0x0564/0x0566)와
  최종 저장(0x0576). 활성 뱅크는 바이트 0x000B(V4) 또는 «CFG5»(FW5)에서 읽고 쓰기 전에 다시
  확인: 무전기에서 다른 뱅크가 선택되어 있으면 아무것도 쓰지 않습니다. V4와 FW5는 바뀐 블록만 쓰고
  보정값(0x1E00부터), FW5 구성과 라이선스는 절대 쓰지 않습니다. V6는 데이터 링크로 인식. 형식은
  IJV가 공개한 CHIRP 모듈(3.60, V4.0, V5.0)과 RadioManager 4.3.2 분석에서 가져왔고 코드는
  처음부터 새로 작성.
- IJV 설정(settings_ijv.go, 새 파일): 주요 메뉴, 디스플레이, VOX, 측면 키(V3, V4), 16개 그룹과
  (V4, FW5) 16개 뱅크 이름.
- UV-K5 펌웨어(fwk5.go): IJV 버전의 .bin 파일은 IJV 탭을 가리키고 경고 표시(V5와 V6는 SYSTEM과
  모듈도 필요).
- Windows 직렬 포트: DTR 끄기 가능(SetDTR), V6 데이터 링크용.
- 카탈로그: Quansheng UV-K5와 UV-K1에 IJV 탭과 IJV 사이트.
- 번역: 모든 언어에 새 텍스트 143개.
- 테스트: 시뮬레이션 IJV 무전기(V3, V4, FW5, V6), 평문 및 순정 프로토콜, FW5 알림, 뱅크 변경,
  쓰기 거부, 보정값을 절대 쓰지 않음.
