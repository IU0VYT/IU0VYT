4.16.0（2026/11/10）
-------------------
- OpenGD77 固件（drv_ogd77.go，新增；协议和存储结构依据自由软件 qdmr 的说明）：两个卡片，分别用于 GD-77 / GD-77S / DM-1801 / RD-5R 和 MD-UV380 系列（DM-1701、MD-UV380、MD-380、MD-9600、MD-2017、RT3S、RT84）；1024 个模拟或 DMR 信道；写入前重新读取电台，只写入信道和区域中有变化的块。
- Quansheng UV-K5：kamilsss655 的 NUNU 固件（drv_uvk5x.go；egzumer 的存储结构，115200 波特，71 项设置）和 joaquim.org 的 UV-KX 固件（drv_uvkx.go，新增；230 个信道，14 项设置，校准数据从不写入）；“OSFW”卡片也接受原厂固件版本，用于修改版原厂固件。
- Radtel RT-880（无 GPS）：Radtel 的软件使用与 CHIRP 的 RT-880G 驱动相同的命令，因此 RT-880 使用该卡片。已确认 amnemonic 固件合集中的 34 个文件均可被 UV-K5 固件更新接受。
- 目录：485 款电台，419 款有设置，图库 539 款，47 个品牌。翻译：47 条新文本。测试：与 kamilsss655 和 joaquim.org 的 CHIRP 驱动比对，OpenGD77 模拟电台。

4.15.0（2026/11/10）
-------------------
- Icom ID-31、ID-51、ID-51 Plus、ID-51 Plus2（drv_id31.go，新增；CHIRP 驱动 id31.py、id51.py、id51plus.py）和 IC-E90 / IC-T90（drv_icx90.go，新增；icx90.py）：Icom 快速复制，500 个信道，模拟或 D-STAR。
- Yaesu VX-6、VX-3（drv_yaesuclone.go、drv_vx6.go，新增；yaesu_clone.py、vx6.py、vx3.py）和 FT-70D、FT1D、FT2D、FT3D、FT5D（drv_ysf.go，新增；ft70.py、ft1d.py、ft2d.py）：复制由电台发起，999 或 900 个信道，模拟或 C4FM。
- Kenwood TH-D74、TH-D75（drv_thd74.go，新增；thd74.py）和 TH-D72（drv_thd72.go，新增；thd72.py）：通过 USB 线的“MCP”协议，1000 个信道。
- 自由固件：TD-H3 的 nicFW 2.x，RT-880、RT-880G 和 RT-950 Pro 的 nicFW880 / nicFW950（drv_nicfw.go、settings_nicfw.go，新增；根据 nicsure 公布的文档从零编写）；UV-K1 和 UV-K5 V3 的 F4HWN Fusion 5.x（drv_uvk5x.go）：1024 个信道和设置。
- 来自 CHIRP 的 10 个新类别的设置。目录：Kenwood 品牌（483 款电台，419 款有设置，图库 537 款，47 个品牌）。翻译：147 条新文本。测试：所有新型号均与 CHIRP 比对并用模拟电台验证。

4.14.0（2026/11/10）
-------------------
- Yaesu FT-4XR、FT-4XE、FT-4VR、FT-65R、FT-65E、FT-25R（drv_ft4.go，新增；CHIRP 驱动 ft4.py）：带回显的 SCU-35 编程线协议，200 个信道；子类型 3 的电台有各自的选项卡，识别功能会选择正确的那个。Yaesu FT-60R/E（drv_ft60.go，新增；ft60.py）：由电台发起克隆，1000 个信道。
- Icom IC-V86、IC-T10、IC-V80、IC-T70、IC-V82、IC-U82（drv_icom.go、drv_icv86.go、drv_icv80.go、drv_icx8x.go，新增；CHIRP 驱动 icf.py、icv86.py、ict10.py、icv80.py、ict70.py、icx8x.py）：单线编程线上的 Icom 克隆协议，IC-V80 使用 38400 波特的快速克隆。
- 来自 CHIRP 的 12 个新类别的设置。目录：Yaesu 和 Icom 品牌，13 款型号（464 款电台，409 款有设置，图库 502 款，46 个品牌）。
- 语言：程序、网站和 GitHub 文件中新增马来语（ms）和印地语（hi）。
- Wouxun KG-UV8D：字段名称与当前的 CHIRP 保持一致。翻译：98 条新文本。测试：与 CHIRP 比对（读取、写入、结构、线上字节）以及模拟的 Yaesu 和 Icom 电台。
- 修正：程序指南中五个加粗的词在所有语言中仍为意大利语。
- 转换器和转发到其他电台（目标为 Yaesu 和 Icom 电台）：电台不具备的亚音会被去掉并给出提示，电台无法存储的信道会被跳过并给出提示，而不再中止整个操作。

4.13.1（2026/11/09）
-------------------
- IJV V6 固件（drv_ijv6.go，新增）：卡片“Quansheng UV-K5 V3 / UV-K1（IJV V6 固件）”。V6 数据连接（DTR 和 RTS 低电平；带 CRC32 的“A5 5A”请求，12 字节的“5A A5”应答）：信息和版本、按预告的请求数打开、256 字节读取、256 字节页面按 4 KiB 扇区确认、结束和重启。存储器与 V5 相同（存储库 n 位于 0x020000 + n·0x4000，当前存储库取自“CFG5”，写入前重新读取）。只写入更改过的扇区，每个都回读比较；校准、许可以及电台自行管理的区域保持电台上的内容。
- 当电台只响应 V6 数据连接时，其他 IJV 卡片会指出 V6 卡片。
- 设置：V6 使用 V5 的表。目录和 UV-K5 固件：加入 V6 卡片。
- 翻译：23 条新增或修改的文本。测试：模拟 V6 电台（读取、只写更改的扇区、存储库已更改、设置被拒绝、卡片错误）。

4.13.0（2026/11/09）
-------------------
- 适用于 Quansheng UV-K5 / UV-K5 V3 / UV-K1 的 IJV 固件（drv_ijv.go，新增）：四个卡片，
  200 信道的 V3（0x0500，8 KiB 镜像）、999 信道的 V3 X（0x2000-0x9FFF）、V4 和 V5（电台
  上选定存储库的 500 个信道，24 KiB 镜像：固定区 0x0000-0x1FFF，存储库在
  0x2000-0x5FFF）。32 字节信道记录；保留分组、AGC、压扩、加扰、选呼、发射锁定和繁忙锁定。
  连接：V3 使用 UV-K5 原厂协议；V4 和 FW5 使用 IJV 明文协议，无应答时改用原厂协议；FW5
  使用物理读写（0x0564/0x0566）和最终保存（0x0576）。活动存储库取自字节 0x000B（V4）或
  “CFG5”（FW5），写入前重新读取：若电台上选的是其他存储库，则不写入任何内容。V4 和 FW5
  只写入有变化的块；从不写入校准数据（自 0x1E00 起）、FW5 的配置和许可。V6 通过其数据
  连接识别。格式取自 IJV 发布的 CHIRP 模块（3.60、V4.0、V5.0）和对 RadioManager 4.3.2
  的分析；代码从零编写。
- IJV 设置（settings_ijv.go，新增）：主要菜单、显示、VOX、侧键（V3 和 V4）、16 个分组
  和（V4、FW5）16 个存储库的名称。
- UV-K5 固件（fwk5.go）：带 IJV 版本的 .bin 文件指向 IJV 卡片并给出警告（V5 和 V6 还需要
  SYSTEM 和模块）。
- Windows 串口：可关闭 DTR（SetDTR），用于 V6 数据连接。
- 目录：在 Quansheng UV-K5 和 UV-K1 中加入 IJV 卡片和 IJV 网站。
- 翻译：所有语言新增 143 条文本。
- 测试：模拟 IJV 电台（V3、V4、FW5、V6）、明文和原厂协议、FW5 通告、存储库变化、写入被拒、
  从不写入校准数据。
