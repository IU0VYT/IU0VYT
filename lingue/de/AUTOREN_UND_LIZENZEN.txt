FIRMWARE-AKTUALISIERUNG DER QUANSHENG UV-K5 (4.1)
Das Format der .bin-Dateien von Quansheng und das Protokoll des Laders der UV-K5 sind
von den freien Programmen k5prog (Copyright 2023 Jacek Lipkowski SQ5BPF, GNU GPL v3,
https://github.com/sq5bpf/k5prog) und uvtools (egzumer,
https://github.com/egzumer/uvtools) dokumentiert. fwk5.go ist auf Grundlage dieser
Dokumentation von Grund auf neu geschrieben, für die Interoperabilität; kein Code
dieser Programme ist im Paket enthalten. verifica/k5/k5ref.js, nur für die Tests
verwendet, lädt den Code von uvtools aus dem Ordner, den die prüfende Person angibt.
Dank an SQ5BPF und an egzumer.

FIRMWARE-AKTUALISIERUNG DER TIDRADIO TD-H3 / TD-H8 UND RADTEL RT-730 (4.3)
Das Protokoll des Laders ist von nicsure im Projekt TD-H3-Engineering dokumentiert
(https://github.com/nicsure/TD-H3-Engineering, firmware_flash_protocol.txt, mit dem
Mitschnitt der Schnittstellen des Herstellerprogramms) und wird von seinem Programm
TID Station verwendet; derselbe Handshake mit 36 Byte steht in den
Herstellerprogrammen „H8_IAP“ (TIDRADIO) und „RT730 Update tool“ (Radtel). fwtdh.go
ist auf Grundlage dieser Dokumentation von Grund auf neu geschrieben, für die
Interoperabilität; kein Code dieser Programme ist im Paket enthalten. Dank an nicsure.

FIRMWARE-AKTUALISIERUNG MIT DEM LADER 7.x (UV-K5 V3, UV-K1, RA79 V3) (4.4)

ZONENNAMEN (4.11)
Das Format der Zonennamen ist, zur Interoperabilität, aus dem Code der
Herstellerprogramme abgeleitet: Radtel RT-950PRO_CPS v1.2.0-v1.3.3 und Bajeton
BJ-9000_CPS v1.3.3 (RT-950 Pro, BJ-9000, HI-UV850 Pro), RT-950_EnCPS „BT-9000_CPS“
v1.3.0 (RT-950), RT-920_EnCPS v1.2.4 (RT-920) und RT910_EnCPS v1.0.3 (RT-910 ohne
Bluetooth), radtels.com und bajeton.cn; für die RT-920 auch aus dem Treiber
radtel_rt900.py von CHIRP (Fred Trimble, GNU GPL, siehe oben). Kein Herstellerprogramm
ist enthalten.
Die Idee, die Zonen zu benennen, und die Sammelbearbeitung der Kanäle stammen aus dem
Programm „RT-950 / 950 Pro Editor“ von Jorge De La Cruz KK4OXN
(https://github.com/cruzerdlc/RT-950-950Pro-Editor, MIT-Lizenz): Das Repository
veröffentlicht nur Dokumente und kompilierte Programme, nicht den Quellcode, und es
wurde kein Code daraus übernommen; die Funktionen sind in IU0VYT Flash von Grund auf
neu geschrieben.

.BTU-FIRMWARE (4.8)
Die .BTU-Firmwares der Radtel RT-910 und RT-900 ohne Bluetooth und der Bajeton BJ-7700
ohne Bluetooth werden mit dem Protokoll des Programms „Radtel Bootload Tools“ (Radtel,
radtels.com) gesendet, für die Interoperabilität aus seinem Code abgeleitet: es ist
derselbe Lader KDH V1.0 wie bei der Baofeng UV-5RM (bfkdh.go), mit dem Handshake
„PROGRAMBT80U“. Die Firmwares (Radtel radtels.com, Bajeton bajeton.com) werden nur an
ihrem SHA-256-Fingerabdruck erkannt; für die RT-900 wurden auch die
Herstellerprogramme „RT900_512 CPS“ v1.0.0 und v1.0.2 (512 und 999 Kanäle) verglichen.
Kein Programm und keine Firmware ist im Paket enthalten.

Die .kdhx-Firmwares der Radtel RT-470 / RT-495 / RT-630 verwenden dasselbe Protokoll
wie der „Bootloader Pro“ der UV-25 Plus (fwkdhx.go), mit der Plattform JJCC, die das
Radtel-Programm „New RT470 serial Bootloader Pro“ angibt.
Die Änderungen gegenüber den Originaldateien von CHIRP (Neuschreiben in Go, nur
Kanäle, Anpassung an die Oberfläche von IU0VYT Flash) sind am Anfang jeder Datei und
in CHANGELOG.txt beschrieben, mit den Daten der Versionen.

AUS CHIRP ABGELEITETE EINSTELLUNGEN (seit 3.6)
----------------------------------------------
Die Einstellungstabellen der mit den CHIRP-Treibern verwalteten Funkgeräte
(sorgenti/settings_chirp.json) entstehen, indem man den Code von CHIRP (GNU GPL,
Autoren wie oben) jeden Eintrag lesen und schreiben lässt
(sorgenti/verifica/chirp/chirpsettings.py): sie enthalten die Position der Daten im
Speicher, die zulässigen Werte und die englischen Namen der CHIRP-Einträge.
Seit 3.7 wird das CSV-Format von CHIRP (Spalten des Treibers generic_csv) vom
Konverter gelesen und geschrieben und mit dem Code von CHIRP verglichen
(sorgenti/verifica/chirp/csvcheck.py, das nicht im Programm enthalten ist).
