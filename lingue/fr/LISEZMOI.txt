DÉMARRAGE
- Double-cliquez sur "IU0VYT Flash.exe". L'écran d'accueil "🏠 Home" s'ouvre et en haut
  se trouvent les onglets fixes "🏠 Home", "📻 Modèles", "Archive des relais" et "ℹ
  Info" ; chaque radio choisie dans la galerie (y compris Baofeng K67 Pro et Bajeton
  8300) s'ouvre dans un onglet supplémentaire, qui se ferme avec ×.
- En mettant à jour depuis la version 2.x, il suffit de remplacer l'exécutable :
  archive, réglages et copies restent où ils sont.
- En mettant à jour depuis la version 2.1 ou antérieure (GestioneCanali.exe) : archive
  des relais, réglages et copies restent les mêmes (dossier
  %APPDATA%\GestioneCanaliRadio) ; l'ancien GestioneCanali.exe peut être supprimé.
- Le programme n'a pas de signature numérique : au premier démarrage, Windows peut
  afficher "Windows a protégé votre ordinateur". Cliquez sur "Informations
  complémentaires" puis sur "Exécuter quand même".
- La fenêtre utilise le composant WebView2, déjà présent dans Windows 11. S'il
  manquait, le programme s'ouvre dans le navigateur par défaut et une petite fenêtre
  permet de le fermer.
- On ne peut ouvrir qu'une seule copie du programme à la fois.

COMMENT ON TRAVAILLE
Avec le câble de programmation :
1. "📻 Lire depuis la radio…" : les canaux de la radio apparaissent dans le tableau.
2. Modifiez les canaux ; enregistrez-les aussi dans un fichier (Enregistrer sous…),
   pour en garder une copie.
3. "📻 Écrire dans la radio…".
Avec les fichiers (comme dans la version 1.0) :
- Ouvrez un fichier .xlc (K67 Pro) ou .dat (Bajeton 8300) enregistré avec le programme
  d'origine ou avec celui-ci, modifiez, enregistrez (Ctrl+S). Les fichiers enregistrés
  ici peuvent aussi être ouverts et écrits avec le programme d'origine.
Quand vous enregistrez sur un fichier existant, la version précédente est conservée à
côté avec l'extension .bak (ex. k67.xlc.bak).

GALERIE DES MODÈLES
- L'onglet "📻 Modèles" affiche toutes les radios Baofeng (catalogue et page de
  téléchargement de baofengradio.com), Bajeton (bajeton.com) et, depuis la 4.0, celles
  des autres marques gérées (Quansheng, Retevis, Radtel, Radioddity, TIDRADIO,
  MaxTalker, Abbree, Intek, Maverick, BTECH, WLN, Zastone, Luiton, TID et, depuis la
  4.1, Hiroyasu, Talkpod, Anysecu). Cherchez par marque ou par nom, même alternatif
  (ex. UV-5RA, MINI-5, GT-3TP, UV-K5), et filtrez par marque (menu "Toutes les
  marques"), type (radioamateur, DMR, GMRS / FRS, PMR446 et usage libre, pour
  enfants), radios avec canaux par câble ou avec firmware.
- En haut les "MODÈLES COMPATIBLES : N", gérés par ce programme (étiquettes "Canaux"
  et "Firmware"), en bas les "MODÈLES NON COMPATIBLES : N", qui ne se programment
  qu'avec le programme du constructeur ou avec des programmes libres : pour ceux-ci il
  y a les liens officiels vers les programmes, firmwares et manuels. N est le nombre
  de modèles (avec la recherche et les filtres, ceux affichés). Depuis la 4.3, un
  trait épais sépare les deux parties.
- Dans chaque partie, les radios sont divisées par type : Radioamateur (VHF/UHF), DMR
  (numériques), GMRS / FRS (États-Unis), PMR446 et radios d'usage libre, Pour enfants
  ; dans chaque division, les radios sont séparées par marque (d'abord Baofeng, puis
  Bajeton, puis les autres par ordre alphabétique, avec le nombre de modèles de
  chacune) et les modèles sont par ordre alphabétique (UV-5R avant UV-17). La fiche de
  chaque radio indique la marque, chacune avec sa couleur (Baofeng en bleu, Bajeton en
  orange, Quansheng en vert, Retevis en rouge, Radtel en violet…).
- Chaque modèle a sa fiche même quand sa gestion est la même qu'un autre : par exemple
  UV-5R, UV-5RA, UV-5RE, GT-3 utilisent le même pilote, de même que BF-888S et
  BF-777S. La note de la fiche indique les modèles ayant la même gestion. Pour les
  modèles équivalents indiqués par la table de CHIRP
  (chirp/share/model_alias_map.yaml, ex. GT-1 = BF-888, GT-5 = UV-82, UV-10R =
  BF-F8HP), la note le dit : la compatibilité est celle indiquée par CHIRP, pas par le
  constructeur.
- Clic sur une radio : son onglet des canaux, la mise à jour du firmware ou la liste
  des liens s'ouvre. Si la radio existe en plusieurs versions (ex. UV-5RX3,
  UV-5R+Pro), choisissez la vôtre : si ce n'est pas la bonne, la radio ne répond pas
  et n'est pas modifiée.

RÉGLAGES DES RADIOS (3.6)
- Bouton « ⚙ Réglages… » dans l'onglet de la radio, après avoir lu la radio par câble
  ou ouvert l'un de ses fichiers. À gauche les groupes (p. ex. « Réception et émission
  », « Afficheur, sons et touches », « DTMF »), en haut la recherche. Chaque élément a
  :
    ⓘ  la description de l'élément (au survol de la souris ; un clic la garde ouverte
    en dessous) ;
    ⚠  sur les éléments sensibles : l'avertissement est dans la description et, avant
    d'appliquer, une fenêtre résume les avertissements et demande confirmation.
  Les éléments modifiés sont mis en évidence ; « Appliquer » les écrit dans la mémoire
  de l'onglet (qui devient « modifié ») : ensuite enregistrez le fichier ou écrivez
  dans la radio comme pour les canaux. « Annuler les modifications » revient aux
  valeurs lues.
- Éléments sensibles : mots de passe (allumage, lecture, écriture), limites de
  fréquence et autorisation d'émission par bande, émission désactivée, durée maximale
  d'émission, VOX, réinitialisation et éléments du menu, PTT-ID et codes émis, alarme
  qui émet, fonction relais, désactivation à distance, programmation Bluetooth,
  verrouillage du clavier.
- K67 Pro / 5RH Pro (53 éléments) : d'après le programme « 5RH PRO », méthodes
  ConvertSetting et SettingConvert.
- Bajeton BJ-8300 (40 éléments ; 41 dans les fichiers de BT-11_CPS v1.0.9, avec «
  Division des canaux ») : fenêtre « Optional Features » du programme ; chaque élément
  est un nombre de l'objet enregistré dans le fichier .dat, modifié sur place (le
  fichier reste identique à celui qu'enregistrerait le programme).
- Bajeton BJ-9000, Radtel RT-950 Pro et RT-950 (57 éléments) : fenêtre « Optional
  Features » des programmes du fabricant ; seuls les bits de chaque élément sont
  modifiés, les autres octets restent ceux de la radio. Les zones actives des bandes

LECTURE ET ÉCRITURE PAR CÂBLE
- Branchez le câble, allumez la radio, choisissez le port COM du câble dans la fenêtre
  (le nom du pilote aide à le reconnaître, p. ex. « USB-SERIAL CH340 (COM3) »). Si le
  port n'apparaît pas, installez le pilote du câble et appuyez sur « Actualiser ».
- Le protocole est celui des programmes d'origine des fabricants (CPS du K67 Pro,
  5RH_PRO, et BT-11_CPS de Bajeton), tiré de leur code : mêmes commandes, même
  chiffrement, mêmes contrôles, mêmes pauses.
    K67 Pro : 19200 bauds (la radio peut demander d'elle-même 115200, comme dans
    l'original), mot de passe de programmation facultatif (8 caractères max.).
    Bajeton 8300 : 57600 bauds.
- Avant d'écrire, par défaut, le programme lit la radio et en enregistre une copie de
  sécurité ; après l'écriture il relit la radio et compare les canaux. Si la radio
  redémarre à la fin de l'écriture, la relecture attend et réessaie jusqu'à ce que la
  radio réponde de nouveau (jusqu'à 45 secondes, 3.9.2).
  Copies et lectures se trouvent dans %APPDATA%\GestioneCanaliRadio\copie_radio (elles
  s'ouvrent comme des fichiers .xlc/.dat normaux). Si la copie de sécurité échoue,
  rien n'est écrit.
- Toute la mémoire est écrite comme le fait le programme d'origine : avec les canaux,
  aussi les réglages généraux contenus dans le fichier ou la lecture sur lesquels vous
  travaillez (menus, VFO, zones, DTMF…). Pour ne pas les changer, partez d'une lecture
  de la radio. Sur le K67 les 128 premiers octets (données de la radio, modèle,
  gammes) ne sont jamais écrasés : le programme les lit dans la radio, comme
  l'original.
- Contrôles avant d'écrire (comme dans l'original) : K67 avec une bande de fréquence
  différente de celle du fichier ou modèle « BF-K6 » non lu auparavant → écriture
  refusée ; données non convertibles → erreur avant de se connecter à la radio.
- La lecture et la copie de sécurité peuvent être interrompues ; l'écriture non (la
  radio resterait avec des données incomplètes). Si l'écriture s'interrompt (câble
  débranché, radio éteinte) recommencez-la : la copie de sécurité est dans le dossier
  indiqué ci-dessus.
- Après une lecture les canaux sont « pas encore enregistrés dans un fichier ».
- Quand la radio est branchée au PC n'utilisez pas le programme d'origine en même
  temps (le port COM ne peut être ouvert que par un seul programme).

MISE À JOUR DU FIRMWARE (BAJETON 8300)
Dans l'onglet « Bajeton 8300 » appuyez sur « ⬆ Mettre à jour le firmware… ». La
fenêtre a trois étapes.
1. Firmware
   - « Fichier sur le PC… » : choisissez le fichier du firmware (.anc, p. ex.
     BJ8300_V0.12_20251112.anc) ou une archive .zip ou .rar qui le contient, même avec
     des archives imbriquées (comme le paquet du fabricant : un .rar contenant un .zip
     avec le .anc).
   - « Depuis Internet » : collez l'adresse du fichier (.anc, .zip ou .rar) et appuyez
     sur « Télécharger ». Les liens de partage d'un seul fichier Google Drive et
     Dropbox fonctionnent aussi. Un lien vers un DOSSIER Google Drive ne peut pas être
     téléchargé : ouvrez le dossier dans le navigateur et copiez le lien du fichier,
     ou téléchargez-le et chargez-le depuis le PC. Les firmwares téléchargés sont
     conservés dans %APPDATA%\GestioneCanaliRadio\firmware.
   - Si les archives contiennent plusieurs firmwares, le programme demande lequel
     utiliser.
   - Contrôles du fichier : format (signature « JLUFW » des firmwares de la radio),
     déchiffrement (le fichier .anc est chiffré : le programme le déchiffre comme
     l'original et vérifie que le contenu est lisible), plateforme identique à celle
     du firmware officiel de la BJ-8300 (YHD15C8_soundbox), nom du fichier, empreinte
     SHA-256 des firmwares officiels connus. Le firmware BJ8300 V0.12 du 12/11/2025
     (le dernier publié par Bajeton) est reconnu comme officiel. Un fichier non valide
     ne peut pas être envoyé ; un fichier avec des signalements (p. ex. plateforme
     différente) demande une confirmation de plus.
2. Radio
   - Choisissez le port du câble et l'état de la radio :
     « Fonctionne normalement » (comme le bouton « Update » du programme d'origine) :
     d'abord la radio est IDENTIFIÉE avec le protocole de programmation de la Bajeton
     8300 (le même que « Lire la radio ») et, par défaut, une copie de ses canaux et
     réglages est lue et enregistrée (Bajeton_prima_del_firmware_….dat dans
     copie_radio). Si la radio ne répond pas comme une Bajeton 8300 la mise à jour NE
     démarre PAS et la radio n'est pas touchée. Ensuite la radio est mise en mode de
     mise à jour et reçoit le firmware.
       « Identifier la radio » fait seulement le contrôle, sans mettre à jour.
     « Ne démarre pas » (mode de récupération, comme le bouton « Click Here If Your
     Radio Can't Work ») : pour une radio restée sans firmware valide. La radio ne
     peut pas être identifiée : le programme, comme l'original, attend environ 12
     secondes que la radio se présente en mode de mise à jour. Appuyez sur « Lancer la
     mise à jour » et mettez aussitôt la radio en mode de mise à jour selon les
     instructions du revendeur (en général en l'allumant avec une touche enfoncée,
     souvent le PTT : la procédure n'est pas documentée).
   - Vitesse du transfert : 115200 bauds (par défaut du programme d'origine) ou 57600.
3. Confirmation
   - Il faut toujours cocher « Je confirme que la radio branchée est une Bajeton
     BJ-8300 ».
   - Quand la radio n'est pas identifiée par le programme (mode de récupération, ou «
     ignorer l'identification automatique ») il faut aussi saisir BJ8300 dans la case.
Pendant la mise à jour une fenêtre montre l'avancement et les messages. N'éteignez pas
la radio et ne débranchez pas le câble ; utilisez une batterie chargée. L'opération ne
peut être interrompue que tant que la radio n'a pas commencé à répondre. À la fin
éteignez et rallumez la radio et vérifiez la version à l'allumage ; si des canaux ou
des réglages ont changé, écrivez dans la radio la copie enregistrée avant la mise à
jour. Si la mise à jour s'interrompt : éteignez et rallumez la radio et recommencez ;
si la radio ne démarre plus, recommencez en mode de récupération.
Protocole : celui du programme du fabricant « BinTe ANC Bootloader » V1.1 (BinTalk),
tiré de son code : paquets AA 55 avec CRC16, 9600 bauds, commande d'entrée en mode de
mise à jour, passage à 10000 bauds puis à la vitesse choisie, envoi des données
demandées par la radio, 5 nouvelles tentatives à 2 secondes d'intervalle. Le programme
d'origine ne contrôle ni le fichier ni le modèle de la radio : les contrôles décrits
ci-dessus sont ajoutés par ce programme.
Les archives .rar (formats RAR 1.5-5, même « solides ») sont ouvertes par le programme
avec le décodeur libre rardecode (licence BSD). Les archives protégées par mot de
passe et celles divisées en plusieurs parties ne sont pas prises en charge.

TABLES DES CANAUX
- Double clic, Entrée ou F2 pour modifier une cellule ; vous pouvez aussi commencer à
  écrire. Échap annule la modification. Sur une ligne vide on commence en écrivant la
  fréquence RX.
- Fréquences en MHz (145.600 ou 145,600). Le décalage s'écrit -0.6, +1.6, +5 : le TX
  est calculé. Pour un TX dans une autre bande écrivez directement la fréquence TX.
- Tonalités : sous-tons CTCSS standard (67.0 … 254.1) ou codes DCS : D023N normal,
  D023I inversé (D023 = normal) ; vide = OFF. « Tonalité TX » ouvre le relais, «
  Tonalité RX » est le squelch à tonalité en réception. Le K67 accepte n'importe quel
  code DCS octal ; la Bajeton les 104 codes standard (D023 … D754).
- Scan : canal inclus ou non dans le balayage (maintenant aussi sur le K67).
- Mode (seulement radios avec canaux numériques) : Analogique ou DMR / Numérique. Sur
  les canaux numériques les sous-tons ne sont pas utilisés et les réglages numériques
  de la radio restent.
- Sélection : clic, Maj+clic (intervalle), Ctrl+clic (ajouter), Ctrl+A (tous).
- Coches (3.9.3) : case à gauche de chaque canal (Maj+clic coche un intervalle, la
  barre d'espace les lignes sélectionnées) ; la case en tête de la colonne coche les
  canaux visibles, « ☑ Tout sélectionner » / « ☐ Tout désélectionner » tous les canaux
  de la radio. « 📻 Transférer vers une autre radio » et « → Archive » utilisent les
  canaux cochés ou, s'il n'y en a pas, ceux sélectionnés. Les coches suivent le canal
  quand vous le déplacez ou le modifiez ; elles ne sont pas enregistrées dans le
  fichier.
- Boutons et touches : Ajouter ; Insérer une ligne (Inser) ; Effacer (Suppr) ;
  Supprimer et compacter (Maj+Suppr) ; Monter/descendre (Alt+↑ / Alt+↓) ; Trier (par
  fréquence, nom, tonalité : si vous avez sélectionné plusieurs canaux il trie
  seulement ceux-là) ; Compacter (retire les vides) ; Copier/Couper/Coller
  (Ctrl+C/X/V) ; Annuler/Rétablir (Ctrl+Z/Y). Le clic droit sur la table ouvre un menu
  avec les mêmes opérations.
- En collant sur des positions occupées le programme demande s'il faut écraser,
  insérer en décalant vers le bas ou utiliser seulement les positions libres.
- Bajeton 8300 : 15 zones de 64 canaux. Choisissez la zone dans la barre au-dessus de
  la table, « Toutes » pour les voir ensemble ; « Déplacer vers la zone » déplace les
  canaux sélectionnés.
- K67 Pro : 640 canaux. Les gammes de fréquence de la radio sont lues dans le fichier
  : les fréquences hors gamme sont mises en évidence en rouge.
- Modification groupée (4.11) : « ✎ Modification groupée… » (aussi depuis le clic
  droit) change ensemble, dans les canaux cochés ou, s'il n'y en a pas, dans ceux
  sélectionnés : puissance, largeur de bande, balayage, ton TX, ton RX (OFF supprime
  le ton), décalage et, là où la radio le permet, l'émission (réception seule). Les
  éléments laissés sur « ne pas changer » restent tels quels dans chaque canal ; les
  sous-tons ne sont pas mis sur les canaux numériques. Les tons et le décalage sont
  contrôlés avant de changer le moindre canal ; Ctrl+Z annule toute l'opération.

NOMS DES ZONES (4.11)
Au lieu de « Zone 1 », « Zone 2 »… on peut donner un nom à chaque zone, comme dans les
programmes du constructeur. Le bouton « ✎ Noms des zones… » (ou le double clic sur une
zone de la barre) ouvre la liste des zones avec leur nom ; la barre des zones et la
ligne d'état montrent « numéro · nom ». Les noms sont dans la mémoire de la radio :
ils se lisent et s'écrivent par câble avec les canaux et s'enregistrent dans le
fichier .img.
- Radtel RT-950 Pro, Bajeton BJ-9000, Hiroyasu HI-UV850 Pro (firmware jusqu'à 0.23 :
  15 zones ; à partir de 0.24 : 10 zones) et Radtel RT-950 (15 zones) : jusqu'à 12
  caractères ; lettres sans accents, chiffres, symboles et caractères chinois (GB2312,
  2 octets chacun), comme les programmes du constructeur RT-950PRO_CPS v1.2.0-v1.3.3,
  BJ-9000_CPS v1.3.3 et BT-9000_CPS v1.3.0 (zone mémoire 0xC000, 16 octets par zone).
- Radtel RT-920 (firmware V0.17 et suivants, 10 zones) : jusqu'à 10 caractères, comme
  le pilote de CHIRP (le programme du constructeur v1.2.4 en permet 12 ; zone mémoire
  0xC800).
- Radtel RT-910 / Bajeton BJ-7700 sans Bluetooth (15 zones) : jusqu'à 12 caractères
  sans accents, comme le programme du constructeur RT910_EnCPS v1.0.3 (zone mémoire
  0xA200).
- Radios DMR Baofeng RD-5R, DM-1801 et DM-32UV : on renomme les zones existantes
  (jusqu'à 16 caractères) ; chaque zone doit avoir un nom.
- Sécurité : pour RT-950 Pro, BJ-9000, HI-UV850 Pro, RT-950 et RT-910, la zone mémoire
  des noms n'est écrite que si les noms changent, et elle est d'abord relue depuis la
  radio : si elle contient des données qui ne sont pas des noms (firmware sans noms de
  zones), rien n'est écrit et un message apparaît. Un nom vide laisse la zone telle
  que la radio l'affiche. Pour la RT-920, cette zone mémoire fait partie de celles qui
  sont toujours écrites, comme le fait CHIRP.
- Les fichiers .img de la RT-950 enregistrés avant la 4.11 ne contiennent pas les noms
  : relisez la radio pour les voir. Si la radio ne répond pas à la lecture des noms
  (ancien firmware), le fichier reste sans noms et tout le reste fonctionne comme
  avant.

COPIE ENTRE LES DEUX RADIOS
Copier dans le premier onglet et Coller dans l'autre (depuis la 3.9.3 « Copier vers… »
est devenu « 📻 Transférer vers une autre radio », qui écrit directement dans la radio
branchée : voir « TRANSFERT VERS UNE AUTRE RADIO ») adapte les canaux avec la logique
du convertisseur et montre les avertissements :
- noms : 16 caractères max. sur le K67, 12 sur la Bajeton (abréviations M. S. D. et
  numéro final conservé, p. ex. « CAMPOLUNGHINO 3 » → « CAMPOLUNGH 3 ») ;
- puissance : la Moyenne de la Bajeton devient Haute sur le K67 ;
- tonalités DCS : transférées si la radio de destination a ce code, sinon OFF avec
  avertissement ;
- fréquences hors des gammes du K67.
Dans la fenêtre d'insertion choisissez la zone (Bajeton), la position de départ et
s'il faut utiliser seulement les positions libres ou écraser.

TRANSFERT VERS UNE AUTRE RADIO (3.9.3)
« 📻 Transférer vers une autre radio » (dans l'onglet de chaque radio et dans le menu
du clic droit) écrit les canaux choisis directement dans une autre radio branchée par
câble :
1) cochez les canaux (case à gauche ; « ☑ Tout sélectionner » pour tous les canaux de
   la radio) : si vous n'en avez coché aucun, ceux sélectionnés d'un clic sont
   utilisés ;
2) choisissez marque et modèle de la radio de destination dans les deux menus
   déroulants (les modèles sont classés par type) et où mettre les canaux : dans les
   positions libres (les canaux déjà présents dans la radio restent) ou à la place de
   tous les canaux de la radio ;
3) confirmez que le modèle est le bon et que la radio est branchée au câble et allumée
   ;
4) contrôle de compatibilité, comme pour l'archive des relais : fréquences dans les
   gammes de la radio, aucun canal radioamateur sur un appareil PMR446 / GMRS
   (avertissement jaune si la radio accepte quand même ces fréquences), aucun canal
   DMR sur une radio seulement analogique. Vous pouvez annuler, choisir une autre
   radio ou envoyer seulement les canaux compatibles ;
5) choisissez le port du câble et appuyez sur « Transférer et écrire ». Le programme
   lit la radio et en enregistre une copie de sécurité (dossier « copie_radio »,
   fichier « ..._prima_dell_inoltro_... »), adapte les canaux à la radio (noms,
   caractères, tonalités, puissances, canaux en réception seule ou numériques,
   positions bloquées comme les canaux GMRS fixes), les écrit et relit la radio pour
   les vérifier.
Les réglages de la radio (menus, VFO, touches…) restent ceux lus dans la radio : seuls
les canaux changent. S'il manque des positions libres ou si aucun canal n'est
utilisable, le programme s'arrête avant l'écriture et rien n'est écrit dans la radio.
À la fin la fenêtre indique les positions utilisées et les adaptations ; si l'onglet
de la radio de destination n'était pas ouvert, « Afficher les canaux de la radio »
l'ouvre avec les canaux tels qu'ils sont maintenant dans la radio.

CE QUI EST CONSERVÉ
Le programme ne modifie que ce que vous changez. Un fichier ouvert et enregistré sans
modifications reste identique octet par octet. Les données que le programme
n'interprète pas (autres octets de l'enregistrement K67, les champs signalisation/PTT
ID/busy lock/etc. de la Bajeton) restent inchangées et suivent le canal quand vous le
déplacez ou le copiez dans la même radio. Les réglages généraux des radios ne changent
qu'avec « ⚙ Réglages… » (et seulement les éléments que vous modifiez). K67 : quand
vous ajoutez ou supprimez des canaux, les listes des zones, les canaux A/B et le canal
d'urgence sont mis à jour comme le fait le programme d'origine (les zones ne se
modifient pas d'ici).

CORRECTION D'UNE ERREUR DE LA VERSION 1.0 (K67 Pro)
En analysant le programme d'origine on a découvert que le fichier .xlc a deux tables
de bits par canal (« position occupée » et « en balayage »). La version 1.0 utilisait
de mauvaises tables : un canal ajouté dans une position qui était VIDE pouvait être
invisible pour la radio et pour le programme d'origine (les modifications et
suppressions de canaux existants étaient en revanche correctes). Si vous avez
enregistré des fichiers .xlc avec la 1.0 en ajoutant des canaux dans des positions
vides, ouvrez-les avec cette version : les positions concernées sont signalées et il
suffit de réinsérer ces canaux (ou de refaire l'ajout).

ARCHIVE DES RELAIS
- Elle est partagée par toutes les radios et s'enregistre seule, sur le PC, dans :
  %APPDATA%\GestioneCanaliRadio\archivio_ponti.json (copie de sécurité : .bak)
- « Importer… » : depuis Internet (adresse prédéfinie
  https://www.ik2ane.it/pontixls.xls, modifiable ; les adresses utilisées sont
  mémorisées) ou depuis des fichiers .xls, .xlsx, .csv. Il reconnaît la liste d'IK2ANE
  (feuille « ponti »), les CSV de CHIRP, les fichiers exportés par ce programme et les
  feuilles génériques avec des en-têtes comme Fréquence, Shift, Tonalité, Nom,
  Localité, Région, Province, Type, Réseau.
- Valeurs irrégulières interprétées avec bon sens et signalées (lignes jaunes avec ⚠)
  :
    "+5.0MHz", "-600 kHz"         → décalages normaux
    "+1.362,5 MHz"                → 1,3625 MHz (signalé)
    "79,7" "123"                  → 79.7 / 123.0
    "77.0-141.3" "110.9/162.2 loc"→ première tonalité utilisée, les autres indiquées
    dans l'avertissement
    "82.2" (non standard)         → 82.5, signalé
    "CC1" (color code DMR)        → pas de sous-ton, noté dans les notes
    "DCS023", "1750", "DG-ID:10"  → notés/signalés
    "input" / "output"            → simplex, signalé
  La valeur d'origine reste visible dans le panneau de détail. Les lignes sans
  fréquence valide (p. ex. les marqueurs 9999999 et les lignes de texte finales) ne
  sont pas importables : elles sont listées dans la fenêtre, pas écartées en silence.
- Du fichier d'IK2ANE on lit aussi les couleurs de la légende : relais plus actifs,
  momentanément hors service, pas H24, tonalité non régionale, décalage non standard.
- Filtres (à l'importation, à l'exportation et dans l'archive) : bande
  (VHF/UHF/Autres), type (Analogique, EchoLink, SvxLink, DMR, C4FM, D-Star, NXDN,
  Multimode, HotSpot, Transpondeur, Winlink), état, région, province, réseau, texte
  libre, seulement les lignes avec avertissements ; plus la coche ligne par ligne. À
  l'importation les filtres partent de « seulement les relais utilisables en
  analogique, hors inactifs » : vous pouvez les changer.
- Nom du canal : modèle au choix avec {LOC} {SIGLA} {NOMINATIVO} {PROV} (localité,
  sigle, indicatif, province ; p. ex. « {NOMINATIVO} {LOC} » → « IR0XX M.ALTO »). «
  Régénérer les noms… » le réapplique.
- Relais déjà présents (même fréquence, TX, localité et sigle) : vous pouvez ajouter
  seulement les nouveaux, mettre à jour ceux présents (le nom que vous avez donné
  reste) ou tout remplacer.
- Cochez les relais à mettre dans la radio : case à gauche de chaque ligne (la barre
  d'espace coche les lignes sélectionnées), ou « ☑ Tout sélectionner » et « ☐ Tout
  désélectionner », qui valent pour les relais visibles avec les filtres actuels. Les
  coches restent enregistrées dans l'archive, même à la fermeture du programme.
- « 📻 Transférer vers la radio » écrit dans la radio les relais cochés (s'il n'y en a
  pas, ceux sélectionnés d'un clic) :
    · si une radio a déjà été choisie (celle indiquée dans la barre bleue « Radio de
      destination », c'est-à-dire la dernière utilisée ou le dernier onglet radio
      ouvert) une fenêtre apparaît avec le modèle et la demande de confirmation («
      Confirmer et écrire », ou « Choisir une autre radio… ») ;
    · sinon s'ouvre la liste de toutes les radios compatibles, avec recherche :
      classée par marque (Baofeng, Bajeton) et par type, chaque modèle étant listé
      seul par ordre alphabétique (entre parenthèses la gestion utilisée, p. ex. «
      UV-5RA (gestion : Baofeng UV-5R) », ou la version, si la radio en a plusieurs).
  Avant d'écrire, le programme contrôle que les relais sont compatibles avec la radio
  choisie :
    · fréquences de réception et d'émission dans les gammes de la radio ;
    · aucun relais radioamateur sur un appareil PMR446 / d'usage libre (seulement
      446,0-446,2 MHz) ou GMRS / FRS (seulement 462,55-467,725 MHz) ;
    · aucun relais seulement numérique (DMR, C4FM, D-Star, NXDN) sur une radio
      seulement analogique ; sur les radios DMR (DM-32UV, DM-1801 Pro, DM-5000) les
      relais seulement DMR deviennent des canaux DMR.
  Exception : certaines radios vendues comme PMR446 / usage libre ou GMRS acceptent
  aussi les fréquences radioamateurs (les gammes du pilote sont celles du programme du
  fabricant, p. ex. BF-T17 PMR446 400-480 MHz). Pour les relais dans ces gammes un
  avertissement jaune apparaît avec « Écrire quand même les N relais » : l'écriture
  est permise (aussi depuis l'onglet de la radio, en collant ou en insérant les
  relais). Respectez la réglementation : émettre sur les fréquences radioamateurs
  exige une licence, et un appareil PMR446 homologué ne doit pas être utilisé hors de
  ses canaux.
  S'il n'y a pas de problème les relais sont envoyés ; sinon un avertissement apparaît
  (« Vous avez choisi un appareil non compatible avec les données que vous essayez
  d'envoyer à la radio ») avec la liste des problèmes, et rien n'est écrit dans la
  radio : vous pouvez annuler, choisir une autre radio ou, si une partie des relais
  est compatible, envoyer seulement celle-ci.
  Ensuite s'ouvre la fenêtre d'insertion habituelle (position de départ, seulement
  positions libres ou écrasement, adaptations pour la radio) ; si la radio n'a pas
  encore été lue le programme propose de la lire par câble ou d'en ouvrir un fichier.
  « Changer de radio… » dans la barre bleue change la destination.
- « Copier » copie les relais cochés (ou sélectionnés) pour les coller dans une radio
  (Ctrl+V).
- « 🗑 Supprimer » (3.9.3) retire de l'archive les relais cochés, même ceux cachés par
  les filtres (la confirmation dit combien), ou, s'il n'y en a pas, ceux sélectionnés
  d'un clic ; la touche Suppr supprime les lignes sélectionnées. « 🗑 Tout supprimer »
  vide l'archive. Les deux demandent confirmation et s'annulent avec ↶ (Ctrl+Z) tant
  que le programme reste ouvert ; pour recharger la liste d'IK2ANE utilisez « ⬇
  Importer… ».
- « Marquer comme vérifiés » retire les avertissements après contrôle (ils restent
  dans les notes).

CONVERTISSEUR ET FORMATS UNIVERSELS (3.7)
- Onglet « 🔁 Convertir » : 1) choisissez le fichier de départ ou un onglet ouvert ; 2)
  choisissez le format de destination (recherche par nom) ; 3) « Convertir et
  enregistrer… ». Après la conversion la liste montre toutes les adaptations (noms
  raccourcis, puissances, tonalités non disponibles, canaux hors gamme ou exclus) et «
  Ouvrir dans l'onglet de la radio » ouvre le fichier produit.
- Fichiers de départ : .xlc (K67), .dat (Bajeton, v1.0.8 ou v1.0.9), images .img de
  n'importe quelle radio compatible (même enregistrées par CHIRP : le modèle est
  reconnu d'après les données du fichier), CSV de CHIRP (même avec des lignes de
  commentaire), tables Excel ou CSV (exportées d'ici, de l'archive des relais ou
  écrites à la main : il faut une colonne avec la fréquence, p. ex. « RX (MHz) », «
  Frequenza » ou « Frequency » ; facultatifs nom, TX, décalage, tonalités, puissance,
  largeur, scan, RX seul, numérique).
- Destinations : CSV de CHIRP (format universel, s'ouvre avec CHIRP pour n'importe
  quelle radio), Excel .xlsx, CSV pour Excel, fichier .xlc du K67, .dat de la Bajeton
  pour la v1.0.8 ou la v1.0.9 de BT-11_CPS, image .img de chacune des radios gérées
  avec les pilotes. Les canaux restent à la même position si la radio l'a (ou «
  compacter les canaux ») ; ceux en trop vont dans les premières positions libres, les
  autres sont exclus et signalés. Les positions bloquées de certaines radios (p. ex.
  canaux GMRS fixes de la GM-15 Pro) restent celles de la radio.
- Pour l'image .img d'une radio il faut une image de cette même radio, c'est-à-dire la
  copie complète de sa mémoire (l'onglet ouvert après « Lire la radio » ou « Ouvrir…
  », ou un fichier .img enregistré auparavant d'ici ou de CHIRP ; depuis la 3.8 aussi
  avec « 📻 Lire maintenant la radio branchée… » directement depuis le convertisseur) :
  l'image contient les réglages et l'étalonnage de la radio, qu'on ne peut pas
  inventer, et en écrire une « vide » endommagerait la radio. Pour le K67 et la
  Bajeton on peut aussi partir des réglages par défaut des programmes des fabricants.
- « 📥 Importer… » (onglet de chaque radio) et « Exporter… » → « 🔁 Pour une autre
  radio… » utilisent le même convertisseur.

IDENTIFICATION DE LA RADIO (3.8)
- Onglet « 🔎 Identifier » : choisissez le port du câble (ou « USB » pour les radios
  DMR avec câble USB direct : RD-5R, DM-1801, DM-1701) et appuyez sur « Identifier la
  radio ». On peut restreindre la recherche par marque ou type (analogiques / DMR) :
  c'est plus rapide.
- Le programme essaie l'un après l'autre les protocoles de LECTURE (d'abord K67 Pro et
  Bajeton BJ-8300, puis les radios des pilotes, en commençant par celles qui ont un
  onglet ouvert). Les modèles qui commencent la connexion de la même façon ne sont
  essayés qu'une fois (38 tentatives pour les 100 radios par câble ; depuis la 4.1, 60
  tentatives pour toutes les radios par câble). Quand une radio répond elle est lue
  entièrement, comme avec « Lire la radio », et une copie de la lecture est
  enregistrée dans le dossier des copies (copie_radio).
- Le modèle se reconnaît au contenu de la mémoire, comme le fait CHIRP avec les
  fichiers. Beaucoup de radios utilisent cependant le même protocole et la même
  mémoire sans écrire nulle part leur nom (p. ex. les radios de la famille UV-17Pro,
  les PMR de la famille BF-888S) : dans ce cas le programme le dit (« Modèle
  impossible à distinguer par câble ») et fait choisir le bon modèle avant d'ouvrir
  les canaux.
- On voit : marque et modèle, type (analogique FM ou DMR, PMR446, GMRS), gammes de
  fréquence, nombre de mémoires, connexion utilisée, firmware ou identifiant
  communiqué par la radio (p. ex. UV-5R « BFB297 », BJ-8300 « BT-11U V1.00 », firmware
  de la DM-32UV, K67 « 5RH-PRO » ou « BF-K6 »), texte envoyé par la radio pendant la
  connexion, canaux présents ; pour RD-5R, DM-1801 et DM-1701 aussi ID DMR, nom de la
  radio, date de la dernière programmation et (DM-1701) version du programme qui l'a
  écrite. Le numéro de série : aucune de ces radios ne le communique par le protocole
  de programmation (il n'est que sur l'étiquette).
- « Ouvrir les canaux dans l'onglet de la radio » : comme après « Lire la radio ».
- Durées (4.3) : sans radio branchée la recherche complète dure environ 50 secondes
  (81 tentatives ; moins si vous restreignez la recherche par marque ou type) ; on
  essaie d'abord les radios déjà reconnues par le passé (les 24 dernières), puis
  celles avec un onglet ouvert, puis les autres. Une radio qui répond est trouvée dès
  que vient son tour, puis lue.
- Si une radio répond mais que la lecture n'aboutit pas (p. ex. mot de passe, modèle
  différent) les réponses sont listées dans les détails. Si la radio reste bloquée en
  mode de programmation, éteignez-la et rallumez-la.

IDENTIFICATION AUTOMATIQUE (4.0 - 4.7)
- Dans l'onglet « 🔎 Identifier » appuyez sur « 🔄 Activer l'identification automatique
  ». Dès lors, tant que le programme est ouvert, quand vous branchez le câble de
  programmation (ou une radio DMR par USB) la radio est recherchée toute seule, avec
  les mêmes commandes de LECTURE seule qu'« Identifier la radio » : rien n'est écrit
  dans la radio.
- Cela fonctionne dans n'importe quel onglet du programme. Le cadre « Identification
  de la radio en cours. Veuillez patienter. » (avec « Interrompre ») apparaît en bas
  seulement quand une radio branchée au câble répond vraiment, et disparaît quand la
  radio est reconnue ou que la recherche se termine. Depuis la 4.4 les parasites de la
  ligne (0x00, 0xFF et semblables, typiques d'un câble sans radio ou avec la radio
  éteinte) et l'écho des commandes envoyées, même en retard, ne suffisent pas : il
  faut au moins 4 vrais octets ou deux réponses distinctes. Avec plusieurs câbles le
  cadre n'indique que les ports avec une radio qui répond.
- Quand la radio est reconnue ses données apparaissent (aussi dans une fenêtre) et son
  onglet s'ouvre avec les canaux lus ; si l'onglet avait des modifications non
  enregistrées le programme demande avant de les remplacer.
- Depuis la 4.2, après la reconnaissance la recherche S'ARRÊTE (la fonction reste
  active) : pour rechercher une autre radio sur le même câble appuyez sur le bouton
  jaune « 🔎 Identifier la radio » en haut à droite, à côté de « ? Guide » (depuis la
  4.4 ; il est gris et ne peut pas être pressé si l'identification automatique est
  désactivée ; avec beaucoup d'onglets ouverts il se réduit à la seule loupe). Un
  câble branché au PC ensuite (même le même, débranché et rebranché) est recherché
  tout seul.
- Depuis la 4.3 le programme ÉCOUTE EN CONTINU tous les ports des câbles branchés,
  chacun pour soi et tous ensemble : une radio éteinte ou le volume au minimum
  n'arrêtent pas la recherche, qui recommence aussitôt (sans le cadre) tant que le
  câble reste branché. Vous pouvez donc brancher le câble et allumer la radio ensuite
  : elle est reconnue dès qu'elle répond. Une radio qui répond mais n'est pas parmi
  celles gérées est réessayée toutes les 30 secondes.
- Plusieurs radios branchées à des câbles différents (p. ex. COM6 et COM7) sont
  recherchées en même temps : pour chacune les données apparaissent et l'onglet
  s'ouvre ; si l'onglet est déjà ouvert l'avis « Radio déjà identifiée !! Onglet radio
  déjà ouvert » apparaît (avec plusieurs radios « Radios déjà identifiées !! Onglets
  radio déjà ouverts »). Après la reconnaissance seul le port de cette radio s'arrête
  : les autres restent à l'écoute.
- Les radios reconnues sont mémorisées (même après redémarrage) : les recherches
  suivantes les essaient en premier, et pendant la recherche elles sont réessayées
  toutes les 8 tentatives, ainsi une radio déjà utilisée (p. ex. K67 Pro, Bajeton
  8300, BJ-9000) est reconnue en quelques secondes.
- On ne recherche que sur les ports des câbles de programmation (adaptateurs USB-série
  CH340, Prolific, Silicon Labs, FTDI…), jamais sur les ports Bluetooth, les modems ou
  les ports série du système (COM1, COM2).
- Une recherche automatique en cours s'interrompt d'elle-même quand vous demandez une
  autre opération (lecture, écriture, firmware, transfert ou identification manuelle).
- Le choix reste mémorisé même après la fermeture et le redémarrage du programme. Pour
  ne plus l'utiliser revenez à l'onglet « 🔎 Identifier » et appuyez sur « ⏹ Désactiver
  l'identification automatique ».
- (4.7) Avant d'essayer les modèles le programme écoute le port pendant 1 seconde (une
  fois par minute par port et vitesse). Une radio en mode de mise à jour du firmware
  émet d'elle-même des messages périodiques : ces octets ne comptent pas comme
  réponse, donc la recherche se termine vite et l'onglet Identifier avertit que la
  radio est probablement en mode de mise à jour (éteignez-la et rallumez-la
  normalement, ou utilisez l'onglet Firmware).
- (4.7) Ordre des tentatives : les radios déjà reconnues, celles avec un onglet
  ouvert, puis les plus répandues (K67 Pro, BJ-8300, BJ-7800 / RT-920, BJ-7700 /
  RT-900, BJ-9000 / RT-950 Pro, TD-H8, UV-17 / UV-17Pro, UV-K5, UV-5R, BF-888S), puis
  les autres.

PILOTE USB DE LA DM-1701 (3.8)
- La DM-1701 (et la Retevis RT84) se branche par USB en mode DFU (périphérique
  0483:DF11) et il faut un pilote. Deux possibilités :
  1. le pilote du fabricant (STTub30), dossier « DM-1701 USB Driver » du paquet «
     DM-1701 CPS » : dans la fenêtre « Lire la radio » de la DM-1701 le bouton «
     Installer le pilote USB… » demande l'installateur (dpinst_amd64.exe, ou le
     fichier .inf) et le lance avec l'autorisation de Windows (avec un .inf il utilise
     « pnputil /add-driver … /install », Windows 10 et 11) ;
  2. le pilote générique WinUSB de Windows, installé avec Zadig
     (https://zadig.akeo.ie, Options → List All Devices, périphérique 0483 DF11,
     pilote WinUSB) : le même qu'utilisent dmrconfig et qdmr. Après cette opération le
     programme du fabricant ne voit plus la radio tant que son pilote n'est pas
     réinstallé.
- Le programme utilise de lui-même celui qui est installé ; la fenêtre montre si la
  radio est branchée et avec quel pilote.
- Un pilote Windows ne peut être ni inclus dans le programme ni redistribué : c'est
  pourquoi on utilise l'officiel (ou WinUSB, qui fait partie de Windows).

BTECH DMR-6X2 : MISE À JOUR GUIDÉE DU FIRMWARE (3.8)
- DMR-6X2 (firmware 2.21) et DMR-6X2 PRO (firmware 1.21) sont des radios DMR de la
  marque BTECH (BaofengTech, États-Unis). Le firmware s'installe avec le programme
  officiel « Firmware_Update » du paquet BTECH (menu Tool → Firmware Upgrade du CPS,
  ou C:\DMR_6X2_2.21\Update\Firmware_Update.exe), avec la radio en mode de mise à jour
  : éteinte, maintenez PTT et Alarm (la touche orange) et allumez (la LED clignote en
  rouge) ; port COM du « USB Virtual Com Port Driver », 921600 bauds, Duplex, « Write
  ». Après le firmware (et les icônes, PTT + PF2 à l'allumage) il faut faire la
  réinitialisation (PTT + PF1 à l'allumage) et réécrire le codeplug enregistré
  auparavant : la mise à jour efface la programmation. Source : « STOP and README
  FIRST.pdf » des paquets officiels DMR-6X2-221b et DMR-6X2-PRO-121e
  (https://baofengtech.com/software/).
- Dans la galerie, fiche de la radio → « 🧭 Mise à jour guidée… » : choisissez le
  fichier .spi et le programme contrôle que les fichiers .spi, .CDI et .CDD sont
  cohérents et complets, pour quelle radio ils sont (DMR-6X2 ou PRO : les firmwares ne
  doivent pas être échangés), de quel type de mise à jour il s'agit (firmware, icônes,
  carte APRS) et la version ; il montre la bonne procédure et lance le programme
  officiel (aussi en tant qu'administrateur).
- L'écriture du firmware est faite par le programme BTECH : son protocole n'est pas
  publié et le programme est compilé, donc il n'a pas été possible de le comparer à
  une autre réalisation ; une erreur pourrait rendre la radio inutilisable.

RECHERCHE POUR LES RADIOS NON COMPATIBLES (3.7)
Recherche dans les forums et les sites de passionnés (CHIRP, RadioReference,
miklor.com, RigPix, GitHub) de programmes ou d'astuces pour les radios non compatibles
:
- UV-8D / BF-UV8 : CHIRP ne les gère pas (signalements #1225, toujours ouvert, et
  #4519) : la radio n'indique pas quels canaux sont vides et un pilote d'essai de 2014
  donnait des canaux écrits que la radio ne montrait pas ; elle se programme seulement
  avec le programme du fabricant pour l'UV-8 (en chinois). Non gérée ici : sans ce
  programme le résultat ne serait pas vérifiable.
- DM-5R (Tier I) : dmrconfig gère la TD-5R mais indique expressément « pas la DM-5R »
  ; la radio utilise un câble différent des autres Baofeng et un programme natif. Non
  gérée (la RD-5R, radio différente, est gérée). Pour la gérer il faudrait (3.8) : son
  programme du fabricant (écrit en C++Builder, donc code machine : il s'étudie avec un
  désassembleur comme Ghidra ou IDR, beaucoup plus lentement qu'un programme .NET) et
  surtout un enregistrement du dialogue entre ce programme et une vraie DM-5R (lecture
  et écriture) fait avec un moniteur de port série, avec le fichier enregistré par le
  programme et le câble spécifique de la radio.
- DM-1702 / DM-1703 : il existe des outils libres (MD1702-tools) qui lisent et
  écrivent la mémoire, mais leurs propres auteurs avertissent qu'avec le firmware L05
  et le chargeur MD1706-V2 ils ont rendu des radios inutilisables : non gérées par
  prudence.
- DM-V1 : programme propre au fabricant, câble micro-USB avec le convertisseur à
  l'intérieur de la radio ; aucun programme libre ne la gère.
- PMR446 sans programme publié (BF-T3, BF-T6…T57, BF-V1…V6A, BF-33C, BF-358…) : pour
  certaines radios semblables les utilisateurs de CHIRP ont utilisé avec un succès
  partiel le pilote de la BF-888 (p. ex. BF-M4, signalement #7215, ensuite ajoutée à
  CHIRP). Ce n'est pas une astuce sûre : sans le programme du fabricant on ne peut pas
  savoir si la mémoire est la même, et écrire une mémoire différente peut bloquer la
  radio.
- 5RHam, BJ-98 Plus, M20D : aucun programme ni information technique n'a été trouvé.

EXPORTATION
Depuis l'archive (avec filtres et coches) ou depuis les canaux d'une radio (tous ou
sélectionnés) :
- Excel .xlsx et Excel 97-2003 .xls (première ligne figée, lignes avec avertissements
  en jaune) ;
- CSV pour Excel italien (séparateur « ; » et virgule décimale) ;
- CSV pour CHIRP : colonnes standard de CHIRP. La puissance est écrite en watts (Haute
  5.0W, Moyenne 2.0W, Basse 1.0W) comme l'attendent les versions récentes de CHIRP ;
  les tonalités utilisent Tone (TX seulement), TSQL (TX et RX identiques), DTCS (même
  code DCS) ou Cross (différentes, aussi DCS→DCS, Tone→DTCS…) ; depuis la 3.7 aussi
  les canaux en réception seule (Duplex « off »), les canaux DMR (Mode « DMR ») et le
  balayage de toutes les radios. CHIRP adapte ensuite la puissance aux niveaux de la
  radio de destination.

DIFFÉRENCES PAR RAPPORT AU CONVERTISSEUR PRÉCÉDENT
- Le K67 conserve maintenant les octets non interprétés de chaque canal au lieu de les
  mettre à zéro.
- CSV CHIRP : puissance en watts au lieu de High/Mid/Low (refusés par les CHIRP
  récents) et tonalités TX et RX différentes écrites comme Cross (auparavant TSQL, qui
  dans CHIRP n'utilise qu'une tonalité).

COMMENT CELA A ÉTÉ VÉRIFIÉ
Le code des deux programmes d'origine a été décompilé et exécuté sur des radios
simulées, à côté de ce programme :
- écriture : mémoire de la radio identique octet par octet et même séquence de
  commandes (K67 : 17 commandes, 49 152 octets ; Bajeton : 505 commandes, 49 984
  octets), avec les fichiers d'exemple comme avec des fichiers modifiés (déplacements,
  suppressions, nouveaux canaux, DCS) ;
- lecture : fichier identique à celui qu'enregistre le programme d'origine (date à
  part) ; Bajeton : les 15 600 champs du .dat identiques ;
- le programme d'origine rouvre et réenregistre les fichiers de ce programme sans
  autres modifications ;
- mot de passe erroné, radio éteinte, bande différente, refus des données,
  interruptions, copie de sécurité et vérification sont testés par des tests
  automatiques.
IL N'A PAS ÉTÉ POSSIBLE DE LE TESTER AVEC DE VRAIES RADIOS. Au premier essai : partez
d'une lecture, enregistrez-la dans un fichier et gardez-la de côté ; puis essayez
d'écrire.
Mise à jour du firmware (2.1) : le code ORIGINAL du programme « BinTe ANC Bootloader »
(chargé directement depuis son exécutable) et ce programme ont été reliés à la même
Bajeton simulée dans 10 situations (mise à jour à 115200 et à 57600 bauds, mode de
récupération, fichiers de longueur quelconque, réponses perdues, CRC erronés,
changement de vitesse perdu, radio éteinte, vrai firmware V0.12 avec 700 Ko de
données) : dans tous les cas la radio simulée a reçu les mêmes paquets, aux mêmes
vitesses et avec les mêmes données, et les résultats sont identiques (mêmes
tentatives, mêmes erreurs). L'exécutable Windows a aussi été testé sous Wine avec de
vrais ports série (pseudo-terminaux) : mise à jour et récupération achevées,
changements de vitesse corrects. La mise à jour du firmware non plus N'a PAS été
testée avec une vraie radio : le comportement de la radio est reconstitué d'après ce
qu'attend le programme d'origine.

Nouveautés de la 3.0, mêmes vérifications :
- pilotes de CHIRP : le vrai CHIRP (dossier des sources) et ce programme comparés sur
  chaque modèle : lecture des canaux depuis les images de test de CHIRP (tous les
  canaux identiques), jusqu'à 18 modifications par modèle (nouveaux canaux, relais,

- firmware .BF : le code ORIGINAL du « BF Upgrade Tool for TFT 330L Series » (chargé

LIMITES
- Les protocoles et les formats sont propriétaires et reconstitués à partir des
  programmes d'origine : conservez toujours les copies de sécurité.
- Les zones du K67, de la DM-32UV, de la DR-1801UV et des radios DMR USB ne se
  modifient pas d'ici (elles sont seulement maintenues cohérentes) ; pour contacts,
  groupes et réglages DMR utilisez le programme du fabricant.
- Réglages : les descriptions des éléments des radios CHIRP sont écrites à partir du
  nom anglais de l'élément (beaucoup de pilotes utilisent des noms différents pour la
  même fonction) : le nom d'origine est toujours indiqué à la fin de la description.
- Au moins certains K67 Pro s'identifient comme « BF-K6 » (vérifié avec une vraie
  radio, 3.7) : l'écriture démarre si la dernière radio lue était du même modèle,
  comme dans le programme d'origine (avec la copie de sécurité activée la lecture se
  fait d'elle-même).
- Identification : certaines radios différentes utilisent le même protocole et la même
  mémoire sans indiquer leur modèle : dans ce cas le programme propose les modèles
  possibles et le choix vous revient. Une radio qui répond à un protocole d'une autre
  famille pourrait rester en mode de programmation : éteignez-la et rallumez-la.
- Le téléchargement depuis Internet utilise la connexion directe (pas le proxy du
  système).
- Radios gérées avec les pilotes de CHIRP : les limites de CHIRP pour ce modèle
  s'appliquent (p. ex. BJ-7800 écrit pour le firmware V0.15P ; si la radio a un
  firmware plus récent et ne répond pas comme prévu, la lecture s'arrête sans modifier
  la radio).
- Firmware : la procédure pour faire entrer en mode de mise à jour une radio bloquée
  n'est pas documentée par le fabricant. L'identification automatique reconnaît les
  radios qui utilisent le protocole de programmation de la Bajeton 8300 (BT-11) : une
  radio différente avec le même protocole ne serait pas distinguable, c'est pourquoi
  votre confirmation est aussi nécessaire.

RECOMPILER À PARTIR DES SOURCES (facultatif)
Il faut Go 1.22 ou ultérieur. Dans le dossier « sorgenti » :
      go build -mod=vendor -trimpath -ldflags "-H=windowsgui -s -w -X main.buildDate=AAAA-MM-JJTHH:MM" -o "IU0VYT Flash.exe" .
(buildDate est la date de compilation affichée dans l'onglet Info, p. ex.
2026-10-20T21:45.)
L'icône et les propriétés du fichier .exe (nom, version) sont dans res/risorse.rc,
compilé en rsrc_windows_amd64.syso (la commande est écrite en tête du fichier .rc).
(Les bibliothèques sont déjà incluses dans le dossier vendor ; l'icône est dans
rsrc_windows_amd64.syso.)
Sous Linux « go test -mod=vendor . » exécute les tests automatiques sur les fichiers
d'exemple de testdata et avec les radios simulées. Le dossier « verifica » contient
les programmes de comparaison avec le code d'origine (voir
verifica/LEGGIMI_VERIFICA.txt).
Les tests sur l'importation de la liste des relais d'IK2ANE demandent le fichier
testdata/pontixls.xls (non inclus : données de tiers, téléchargeable sur
www.ik2ane.it).
