4.20.0（2026/11/11）
-------------------
- Radtel RT-4D と RT-6D（DMR）および RT-1000 Pro（drv_rt4d.go、新規）。メーカーのソフト（「RT-4D CPS」2.07、「DMR RT-6D」2.06、2026 年 8 月 6 日の「Radtel RT-1000 Pro CPS」）から求めました。Bajeton DM-5000 のソフトより一世代新しく、接続は同じ（115200 ボー、1 KiB ブロック）ですが、チャンネルとゾーンが異なります。チャンネルは 48 バイトで、先頭 5 バイトがビットフィールド、周波数は 10 Hz 単位でバイト 5-12、トーンはバイト 13-16、名前はバイト 32-47。ゾーンは 520 バイトが 250 個で、それぞれ最大 250 チャンネル。ブロック 8（パスワード）、ブロック 16-63（チャンネル）、0x78-0xF7（ゾーン）を読み出します。書き込みはソフトの順序に従い、ゾーンの後で終わります：0x90（設定）と 0x92（VFO）は無線機から読み出したばかりのデータ、0x91（チャンネル 48 ブロック）、0x93（ゾーン 128 ブロック）。既存チャンネルの扱わない項目は保持されます。108〜136 MHz ではチャンネルを AM で書き込みます。
- 確実でないため行っていないこと：ゾーン内で A/B/C に選ばれたチャンネル（ソフトの保存方法と読み戻し方法が一致しないため、そのバイトは保持します）。RT-1000 Pro のスキャン除外（ソフトはあるビットに書き、別のビットから読むため扱わず、そのバイトはそのままです）。
- カタログ（catalog_420.go、新規）：3 項目。集計：無線機 502、設定対応 427、ギャラリー 556。翻訳：新しいテキスト 13 件。

4.19.0（2026/11/11）
-------------------
- Radtel RT-817A / RT-871A（drv_iradio.go、種類 irRT871A）。メーカーのソフト（「Radtel RT-871A CPS」。RT-860 のソフトと同じコードベースで、メソッドごとに比較）から求めました。プログラミングモードへの入り方、1 KiB のブロック、48 バイトのチャンネルは RT-880G と同じで、ゾーンはありません。読み込むのはブロック 8-11（設定）、0x10-0x3F（1024 チャンネル）、0x358（FM ラジオ）。書き込むのは領域 0x90（4 ブロック）、0x91（48）、0x99（1）。ロゴは扱いません。出力 0 低、1 中、2 高。12 バイトのチャンネルコードは保持します。周波数範囲は 18-660 と 840-1000 MHz。
- カタログ（catalog_419.go、新規）：1 項目。集計：無線機 499、設定対応 427、ギャラリー 553。翻訳：新しいテキスト 3 件。
- 調査したが未対応：Radtel RT-4D、RT-6D、RT-1000 Pro（より新しい世代のソフトで、領域の配置が異なるため新しいドライバーが必要）、Kenwood TK-2180 / TK-3180（tk8180.py はゾーンに応じてメモリー形式を組み立て、独自のヘッダーを持つファイルを使うため、既存チャンネルの単純な変更には縮小できません）。

4.18.0（2026/11/11）
-------------------
- Kenwood TK-2140 と TK-3140（drv_kwtk140.go、新規。CHIRP の tk3140.py：TK-2140K、TK-3140K、TK-3140K2、TK-3140K3）および Kenwood TK-280 と TK-380（drv_kwtk280.go、新規。CHIRP の tk280.py）：48 バイトの 250 の位置がゾーンまたはグループに分かれています。プログラムの一覧は物理的な位置の一覧です。変更したチャンネルは同じゾーンに同じ番号で残り、新しいチャンネルは直前のチャンネルのゾーンに空いている最初の番号で入ります。位置の表は CHIRP と同じように作り直します。
- CHIRP との比較ツール（verifica/chirp/chirpref.py）：CHIRP でゾーンごとに「サブ無線機」を持つ機種に対応しました。6 機種とも、読み込み、15 件の変更、メモリー構成、やり取りするバイト、最終メモリーが CHIRP と一致します。設定：6 クラスを追加（合計 314）。TK-280/380 のグループごとの 750 項目は含みません。
- fagci の R3b0rn ファームウェアを入れた Quansheng UV-K5 / UV-K6（drv_fagci.go、新規）。ファームウェアのソースコードから：設定、VFO、40 個のプリセットは 0x0000～0x052E。23 バイトのチャンネルは EEPROM の末尾から逆順。EEPROM の種類は先頭バイトの下位 3 ビット（8～256 KiB：298、654、678、1024 チャンネル）。32 ビットアドレス、8 バイト単位の書き込み、38400 ボー。書き込むのはチャンネル領域だけです。拒否するもの：32 ビット読み出しに応答しないファームウェア、プリセット数が 40 でないもの、初期化されていないメモリー、サイズの異なるメモリー。レコードはファームウェアの構造体をコンパイルして再確認しました。ファームウェアと一緒に公開されている CHIRP ドライバーとの意図的な違い：送信周波数は常にそのまま書き込み、名前は 9 文字。
- Radtel RT-330 と RT-400（drv_jc8810.go）。メーカーのソフト（「Radio CPS」と「JJCC-7700 CPS」）から求めました。どちらも MML JC-8810 ファミリーのプロトコルとチャンネルレコードを使います。RT-330：ハンドシェイク文字列「PROGRAMYF68U」、115200 ボー、512 チャンネル、100-520 MHz。RT-400：ハンドシェイク文字列「PROGRAMJC81U」（RT-470 と同じ）、57600 ボー、256 チャンネル、18-1000 MHz。メーカーのソフトは識別子を確認しないため、このタブは同じハンドシェイク文字列を使うほかのモデルの識別子を拒否します。シミュレートした無線機でのみ確認。
- カタログ（catalog_418.go、新規）：4 項目、および UV-K5 に R3b0rn のタブ。集計：無線機 498、設定対応 427、ギャラリー 552。翻訳：新しいテキスト 29 件。
- このバージョンで未対応：Kenwood TK-2180 / TK-3180（CHIRP では追加や削除のたびにメモリー全体が移動します）、Radtel RT-871A、RT-1000 Pro、RT-4D、RT-6D、RT-5D（領域やレコードが対応済みのものと異なります）。

4.13.1（2026/11/09）
-------------------
- IJV V6 ファームウェア（drv_ijv6.go、新規）：タブ「Quansheng UV-K5 V3 / UV-K1（IJV V6 ファームウェア）」。V6 のデータリンク（DTR と RTS は Low、CRC32 付きの「A5 5A」要求、12 バイトの「5A A5」応答）：情報とバージョン、予告した要求数でのオープン、256 バイト単位の読み込み、256 バイトのページを 4 KiB セクター単位で確定、終了と再起動。メモリは V5 と同じ（バンク n は 0x020000 + n·0x4000、現在のバンクは「CFG5」から取得し書き込み前に再読込）。変更されたセクターだけを書き、1 つずつ読み戻して比較します。校正データ、ライセンス、無線機が自分で管理する領域は無線機の内容のままです。
- 無線機が V6 のデータリンクにしか応答しない場合、ほかの IJV タブは V6 タブを案内します。
- 設定：V6 は V5 の表を使います。カタログと UV-K5 ファームウェア：V6 タブを追加。
- 翻訳：新規または変更されたテキスト 23 件。テスト：模擬 V6 無線機（読み込み、変更セクターのみの書き込み、バンク変更、設定の拒否、間違ったタブ）。

4.13.0（2026/11/09）
-------------------
- Quansheng UV-K5 / UV-K5 V3 / UV-K1 用 IJV ファームウェア（drv_ijv.go、新規）：4 つの
  タブ。200 チャンネルの V3（0x0500、8 KiB イメージ）、999 チャンネルの V3 X
  （0x2000-0x9FFF）、V4 と V5（無線機で選択したバンクの 500 チャンネル、24 KiB イメージ：
  固定領域 0x0000-0x1FFF とバンク 0x2000-0x5FFF）。32 バイトのチャンネルレコード。グループ、
  AGC、コンパンダー、スクランブラー、セレコール、TX ロック、ビジーロックは保持。接続：V3 は
  UV-K5 純正プロトコル、V4 と FW5 は IJV 平文プロトコル（応答がなければ純正プロトコル）、FW5 は
  物理読み書き（0x0564/0x0566）と最終保存（0x0576）。アクティブバンクはバイト 0x000B（V4）
  または「CFG5」（FW5）から取得し、書き込み前に再確認：無線機で別のバンクが選ばれていれば何も
  書き込みません。V4 と FW5 は変更ブロックのみ書き込み、校正データ（0x1E00 以降）、FW5 の設定と
  ライセンスは書き込みません。V6 はデータリンクで認識。形式は IJV が公開した CHIRP モジュール
  （3.60、V4.0、V5.0）と RadioManager 4.3.2 の解析から取得。コードはゼロから作成。
- IJV 設定（settings_ijv.go、新規）：主なメニュー、表示、VOX、サイドキー（V3 と V4）、
  16 グループと（V4、FW5）16 バンクの名前。
- UV-K5 ファームウェア（fwk5.go）：IJV バージョンの .bin ファイルは IJV タブを示し、警告を
  表示（V5・V6 は SYSTEM とモジュールも必要）。
- Windows のシリアルポート：DTR をオフにできる（SetDTR）。V6 のデータリンク用。
- カタログ：Quansheng UV-K5 と UV-K1 に IJV タブと IJV のサイトを追加。
- 翻訳：全言語に 143 件の新しいテキスト。
- テスト：IJV 無線機のシミュレーション（V3、V4、FW5、V6）、平文と純正プロトコル、FW5 の
  通知、バンク変更、書き込み拒否、校正データは書き込まないこと。
