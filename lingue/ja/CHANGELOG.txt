4.32.0（2026/11/13）
-------------------
- メーカーのプログラムから追加した無線機：Baofeng T22 の FRS 版と TIDRADIO TD-M8S（プログラム「T20 FRS」v1.0.1、両社のパッケージで同じファイル、22 チャンネル）、TIDRADIO TD-V2（プログラム「CPS_F8_FRS」v1.0、16 チャンネル。説明書には Pofung F8、F8i、F8U、F8X、BF-V8 も記載）。チャンネルと一般設定 14 項目。無線機にパスワードが設定されている場合は停止します（メーカーのプログラムで解除してください）。校正データ、ホッピングコード、パスワードは書き込みません。TIDRADIO TD-H4 と TD-H11（標準、HAM、GMRS）は「TIDRadioCPS」（2026）から：接続とメモリーはシリーズの他の機種と同じで、広帯域はプログラムどおり（送信 18-76 MHz と 136-520 MHz、受信 18-800 MHz）。この 2 機種はプログラムに出荷時ファイルがなく、模擬無線機でのみ試しています。修正（4.29 と 4.30 の機種）：中出力があるのは TD-H7 Plus、TD-H8 第 4 世代、TD-H9、TD-H11、TD-638UV だけで、GMRS 版にはありません。他のカードは 2 段階（低 = 0、高 = 2）になりました。値が 1 の出荷時チャンネルはプログラムと同じく「高」と表示し、出力を変更するまで 1 のままです。修正（Baofeng T22 PMR446）：メーカーのプログラムは「PROGRGS」の前に 0x02 を送ります。カードはまず 0x02 付きで、次に無しで試します。「識別」：BF-888S と同じ応答をする新しい 3 機種は、無線機を余分に読み直さずに候補として表示し、そのカードを開いたときにだけその機種のドライバーで読み取ります。他のグループの読み直しは変更していません（ドライバーが無線機を受け付けない機種を除外するためです）。Radtel RT-13、RT-480 / RT-68、RT-830 / RT-850、RT-69 GPS、TIDRADIO TD-M2 Pro の説明を修正。調査のみで追加なし：「H8_4829」は初期世代 TD-H8 用プログラムの新しい版（2024/9/19）で、無線機は対応済み。「DP712」は「DP710 CPS」（DMR、ネイティブコード）を含み、未着手です。

4.31.0（2026/11/13）
-------------------
- 「識別」の高速化（identify.go）：完全な待ち時間の試行（質問ごとに 350 ms、変更なし）の前に高速な一巡を行います：新しい質問ごとに 100 ms、同じ一巡ですでに応答がなかった質問（同じバイト列・同じ速度）は再び待たない、ドライバーが新しい質問をしなくなったら試行をすぐ終える、この PC で識別済みまたはタブを開いている無線機には最初から完全な待ち時間を使う。高速な一巡で見つからなければ、従来どおりの完全な一巡が続きます。模擬無線機での実測：計画の最後の無線機は 26 秒で見つかり（以前は 100 秒超）、無線機なしの完全な検索は約 128 秒（以前は 103 秒）。連続待ち受けでは 1 回おきに高速な一巡のみを行います。「識別」は 4.26 から 4.30 で追加した無線機も試します（Retevis RB39 / RB639, C6, C66, Radioddity Echo, UB15-G, DB35-G, DB35-UV, DB40-G、TIDRADIO TD-M2 Pro。TIDRADIO TID-712Plus ファミリーと UB15-G / DB35-G / DB35-UV はファミリーを識別してカードを提案）。修正（drv_auctus.go）：Retevis RB39 を RB639 のカードで（またはその逆で）読むと、無線機がプログラミングモードから戻されませんでした。未対応：TD-V2、TD-M8S、「H8_4829」、DP712。

4.29.0（2026/11/12）
-------------------
- TIDRADIO TD-H3 Plus と TD-H3 SE、TD-H7 Plus、第 4 世代 TD-H8、TD-H9、TD-638UV（チャンネルのみ）：drv_tdh8.go に新しいカード 15 枚（各機種に標準、HAM、GMRS）。メーカーのプログラム「TIDRadioCPS」（2026/1/23 から 2026/7/27 までの各バージョン）から：接続は TD-H3 と同じ、メモリー配置は CHIRP の TD-H3 と同じ（チャンネルは 0x0010 から、名前は 0x0D40 から、使用中チャンネルは 0x1900、スキャンは 0x1920）。プログラムから得た相違点：識別子（H3 Plus と SE は P31183 / P31185 / P31184、ほかは「TDH7PLU」「TDH84GE」「TDH9」「TD638UV」に N、H、G のいずれかが続く）、読み書きするアドレスは 0x0000-0x1F3F、書き込み前にファームウェアのバージョンを読まない、セッションは 32 バイトの「CE」ブロックで終了、出力は 3 段階（0 低、1 中、2 高）、空のチャンネルは周波数がゼロで使用中の印がない、チャンネル内の追加の 2 フィールド（スクランブラーのグループ、受信モード）は保持。範囲：標準 108-174 と 200-600 MHz（108-136 は受信のみ）、HAM の送信は 144-148 と 420-450 MHz。
- 確認：プログラムに含まれる 15 の出荷時ファイルをすべて読み取り（それぞれ 32 または 41 チャンネル、使用中の印が付いたチャンネル数と同じ、範囲外の周波数なし）、チャンネルごとに書き直しても差異なし。ただし HAM 版の気象チャンネルは受信のみになります。CTCSS と DCS の符号化をプログラムのコードで再確認。模擬無線機。同じファミリーの CHIRP 機種は変更なし。未追加：同じプログラムの H4 と H11（パッケージに出荷時ファイルがない）と、これらの機種の一般設定。対応済みで TIDRADIO のパッケージで再確認したもの：第 3 世代までの TD-H8、TD-H3、22 チャンネルの TD-M11、TD-M8。今後調べるもの：TD-M2Pro、TD-FRS / TD-PMR、TD-V2、TD-M8s、DP712。数：無線機 562、設定付き 476、ギャラリー 616、52 ブランド。翻訳：新しいテキスト 24 件。

4.28.0（2026/11/12）
-------------------
- Radioddity UB15-G、DB35-G（プログラムの名前は「DB-35G」）、DB35-UV、DB40-G、車載機：新しいドライバー（drv_wf.go）。メーカーのプログラムは全機種共通で、速度、ハンドシェイク、アドレス、各フィールドの位置を隣にある設定ファイルから取ります。残りはそのコードから読み取りました。無線機タイプの問い合わせ（55 01 00 00）、3 段階のハンドシェイク（02「PROGRAM」、02 →「SMP558」、06）、行番号による読み取り 'R' と書き込み 'W'、最後に 'b'。設定はアドレス E0 00 の 1 行です。チャンネルの行：受信と送信が各 4 バイト（Hz）、トーンが各 2 バイト（CTCSS は 0.1 Hz 単位、DCS は 0x2800 + コード、反転は 0xA800）、続いて出力、帯域幅、スキャン、そしてある場合は大文字 8 文字の名前。ビジーチャンネルロックと優先はチャンネルのまま残ります。UB15-G：88 行（チャンネル 1-15、次に「15RP」、16、「16RP」… 22、「22RP」、その後 23-80）で、カードは 2 枚あります。ファームウェア V1.10 では行が長くなり名前が入るためです。別タイプの無線機はハンドシェイクの前に分かりやすいメッセージで拒否されます。無線機から一度も読み取っていないイメージは設定に触れません。
- DB40-G：2026 年 11 月から CHIRP にもあります（radioddity_db40g.py）。ここでは CHIRP と同じことをバイト単位で行い（タイプの問い合わせなし、読み取りコマンドのエコーを確認、名前は 00 で埋める、削除した行はすべてゼロ）、テストで両者を比較しています：CHIRP のサンプルイメージの 31 チャンネルを差異なく読み取り、18 件の変更で同一のイメージ、読み取り時に 811 バイト、書き込み時に 7211 バイトを送信し、CHIRP と同一でした。これはファミリー全体のハンドシェイク、パケット、アドレス、トーン、周波数の独立した確認にもなっています。
- 設定（settings_wf.go）：スケルチ、最大送信時間、ノイズ低減（オン / オフまたはレベル）、優先チャンネルの監視、キー音、ロジャービープ。ファームウェア V1.10 の UB15-G にはマイクのノイズ低減と VOX も。DB35-UV には VOX、周波数ステップ、バックライト（レベル、消灯、色）も。DB40-G：スケルチ、最大送信時間、ビジーチャンネルロック、キー音。数：無線機 556、設定付き 476、ギャラリー 610、52 ブランド。翻訳：新しいテキスト 45 件。確認：周波数、トーン、各設定のバイトを手計算。新しい模擬無線機を読み取り、書き込み、変換、堅牢性の共通テストに追加。データ競合の検査。確認中に 2 つの誤りを見つけて修正しました：テスト内の手計算の値の誤りと、模擬無線機が接続をまたいで状態を保持していたこと。メーカーのプログラムは一度も実行していません。UB15-G、DB35-G、DB35-UV は実機で試していません。修正：4.26 以降、Windows でテストがコンパイルできませんでした。3 つのテストファイルが、Windows ではビルドされない模擬無線機を使っていたためです。プログラム本体には影響ありませんでした。

4.27.0（2026/11/12）
-------------------
- Retevis C6（FRS / GMRS、30 チャンネル）、Retevis C66（UHF、16 チャンネル）、Radioddity Echo-DE / Echo-IT（PMR446、16 チャンネル）：新しいドライバー（drv_wlt.go）。メーカーのプログラム「C6」「C66」「Radioddity ECHO」（キーとアドレスが違うだけの同じプログラム）のコードから作成。9600 ボー。ハンドシェイク：プログラムは乱数を 2 つ選び、機種のキー（8 バイト）を 1 つ目の数と混ぜて送ります。無線機は 2 つの数から計算した値とキーを混ぜて応答します。次にパスワード（なければ FF）、チェックサム付き 16 バイト単位の 'R' 読み取りと 'W' 書き込み、最後に 'E'。16 バイトのチャンネル：BCD の周波数（10 Hz 単位）、DCS ビット付き BCD のトーン、出力、帯域幅、スキャン。スクランブラー、コンパンダー、ビジーチャンネルロック、周波数ホッピングはチャンネルのまま残ります。読み取りはパスワードのブロックまで、書き込みは範囲のブロックまで。パスワードと調整データは決して書き込みません。書き込み前に、無線機の範囲・機種・地域がイメージと同じであることを確認します。パスワードが設定された無線機や別の機種は、わかりやすいメッセージで拒否されます。
- 設定（settings_wlt.go）：スケルチ、最大送信時間、VOX と感度、音声ガイド、バッテリーセーブ、側面キー（短押しと長押し）。C6 と C66 ではさらに：呼び出しトーン、送信音（ロジャー）、ワンキーペアリング、ワイヤレスコピー。Echo では：VOX 遅延。
- 追加の確認：C6 のプログラムに含まれる 30 の既定チャンネル（FRS / GMRS の 22 とレピーター用の 8）が、正しい周波数、トーン、出力、帯域幅で読めます。このため C6 は 468 MHz までの周波数を受け付けます（プログラムの入力は 467 MHz まで）。
- Retevis RB39 / RB39P：「機種」タブで「GMRS / FRS（米国）」の無線機に入りました（PMR446 に入っていました）。集計：無線機 552、設定対応 472、ギャラリー 606、ブランド 52。翻訳：新しいテキスト 47 件。確認：ハンドシェイクを 3 組の数で手計算し、すべての組み合わせで試験。各アドレスをプログラムのコードで 2 回読みました。読み取り・書き込み・変換・堅牢性の共通テストに新しい模擬無線機を追加。メーカーのプログラムは一度も実行していません。これらの無線機はいずれも実機では試していません。

4.24.0（2026/11/11）

4.13.1（2026/11/09）
-------------------
- IJV V6 ファームウェア（drv_ijv6.go、新規）：タブ「Quansheng UV-K5 V3 / UV-K1（IJV V6 ファームウェア）」。V6 のデータリンク（DTR と RTS は Low、CRC32 付きの「A5 5A」要求、12 バイトの「5A A5」応答）：情報とバージョン、予告した要求数でのオープン、256 バイト単位の読み込み、256 バイトのページを 4 KiB セクター単位で確定、終了と再起動。メモリは V5 と同じ（バンク n は 0x020000 + n·0x4000、現在のバンクは「CFG5」から取得し書き込み前に再読込）。変更されたセクターだけを書き、1 つずつ読み戻して比較します。校正データ、ライセンス、無線機が自分で管理する領域は無線機の内容のままです。
- 無線機が V6 のデータリンクにしか応答しない場合、ほかの IJV タブは V6 タブを案内します。
- 設定：V6 は V5 の表を使います。カタログと UV-K5 ファームウェア：V6 タブを追加。
- 翻訳：新規または変更されたテキスト 23 件。テスト：模擬 V6 無線機（読み込み、変更セクターのみの書き込み、バンク変更、設定の拒否、間違ったタブ）。

4.13.0（2026/11/09）
-------------------
- Quansheng UV-K5 / UV-K5 V3 / UV-K1 用 IJV ファームウェア（drv_ijv.go、新規）：4 つの
  タブ。200 チャンネルの V3（0x0500、8 KiB イメージ）、999 チャンネルの V3 X
  （0x2000-0x9FFF）、V4 と V5（無線機で選択したバンクの 500 チャンネル、24 KiB イメージ：
  固定領域 0x0000-0x1FFF とバンク 0x2000-0x5FFF）。32 バイトのチャンネルレコード。グループ、
  AGC、コンパンダー、スクランブラー、セレコール、TX ロック、ビジーロックは保持。接続：V3 は
  UV-K5 純正プロトコル、V4 と FW5 は IJV 平文プロトコル（応答がなければ純正プロトコル）、FW5 は
  物理読み書き（0x0564/0x0566）と最終保存（0x0576）。アクティブバンクはバイト 0x000B（V4）
  または「CFG5」（FW5）から取得し、書き込み前に再確認：無線機で別のバンクが選ばれていれば何も
  書き込みません。V4 と FW5 は変更ブロックのみ書き込み、校正データ（0x1E00 以降）、FW5 の設定と
  ライセンスは書き込みません。V6 はデータリンクで認識。形式は IJV が公開した CHIRP モジュール
  （3.60、V4.0、V5.0）と RadioManager 4.3.2 の解析から取得。コードはゼロから作成。
- IJV 設定（settings_ijv.go、新規）：主なメニュー、表示、VOX、サイドキー（V3 と V4）、
  16 グループと（V4、FW5）16 バンクの名前。
- UV-K5 ファームウェア（fwk5.go）：IJV バージョンの .bin ファイルは IJV タブを示し、警告を
  表示（V5・V6 は SYSTEM とモジュールも必要）。
- Windows のシリアルポート：DTR をオフにできる（SetDTR）。V6 のデータリンク用。
- カタログ：Quansheng UV-K5 と UV-K1 に IJV タブと IJV のサイトを追加。
- 翻訳：全言語に 143 件の新しいテキスト。
- テスト：IJV 無線機のシミュレーション（V3、V4、FW5、V6）、平文と純正プロトコル、FW5 の
  通知、バンク変更、書き込み拒否、校正データは書き込まないこと。
